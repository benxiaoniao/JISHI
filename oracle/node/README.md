# 基石 JS 引擎（M13.2）

在 **Node.js** 里独立执行基石字节码，**无需 Python、无需 C VM、零第三方依赖**。

## 原理

```
基石源码 ──(Python: jishi --dump-bytecode)──> 字节码 JSON ──(Node)──> 输出
```

- Python 侧用 `jishi --dump-bytecode` 把源码编译成平台无关的 JSON 字节码（M13.1）；
- Node 侧 `index.js` 加载字节码，`vm.js` 逐条解释指令，`runtime.js` 提供语义
  （内建函数 / 列表字典方法 / 类与继承 / 异常匹配 / 浮点装箱）。
- 语义与 Python VM（`jishi/vm.py`）逐字节对齐，由 `tests/test_m13_node.py`、
  `tests/test_m27_display.py`、`tests/test_m30_node_host.py`、
  `tests/test_m31_node_stdlib.py`、`tests/test_m34_pattern_enum.py` 对拍保证。

## 用法

```bash
# 1. 用 Python 编译出字节码（一次性，可分发）
jishi 你的脚本.jsh --dump-bytecode > 脚本.json

# 2. 用 Node 执行（无需 Python 环境）
node node/index.js 脚本.json

# 自测
node node/index.js --self-test
```

## 文件结构

```
node/
├── index.js       # 入口：加载 JSON 字节码 + 解码 + 执行
├── vm.js          # 指令分发（48 条指令）
├── runtime.js     # 语义层（内建/方法/类/异常/浮点装箱）
└── package.json
```

- 标准库 14 个模块（数学 / 文本 / 随机 / 日期 / 时间 / 路径 / 文件 / 表格 /

**暂不支持**（诚实边界）：

- `导入 x 从 python`（Python 生态桥接）—— JS 引擎无 Python 运行时，报中文错误；
- `导入 x 从 本地包`（本地包）—— 同上；
- **`网络` 是子进程封装**：Node 没有同步 HTTP，所以 `获取`/`提交`/`获取JSON`
  会 `spawnSync` 起一个自身的子进程跑异步 `fetch`，结果经 stdout 回传。
  语义与 Python 侧一致（同步、有超时、错误是中文），代价是每次请求多一次
  进程启动（本机实测约 40ms）；
- 标准库里的**日期时间**按本地时区算（与 Python 的 `datetime.now()` 一致），
  JS 的 `Date` 没有时区对象，所以没有「指定时区」的能力；
- **整数溢出**：C 虚拟机是 64 位、Rust 宿主到 i128，本宿主是**任意精度**
  （M32 起按需切 BigInt：任一边是 BigInt，或 number 结果超出安全范围时）；
- **整数与小数的区分**：JS 的 `1` 与 `1.0` 是同一个 number，JSON 字节码也把
  `1.0` 解析成 `1`，所以类型标注 `函数 f(x: 小数)` 遇到**字面量** `f(1.0)`
  会判成「整数」报错（Python 侧放行）。运算得到的小数会装箱成 `FloatBox`，
  判定正常——这是 JS 表示层的固有限制，不是漏做；
- 浮点尾零显示：靠 `FloatBox` 装箱区分整数/浮点，已对齐 Python 的 `5.0` 显示，
  但极端的浮点精度行为与 Python 有差异。

> **精确小数的实现说明**：JS 侧用「系数(BigInt) × 10^exp」自己实现十进制，
> 加减乘精确、除法算到 28 位有效数字（与 Python 的 `decimal` 默认上下文一致）、
> 舍入用 half-even——因此 `精确("1")/精确("3")` 这类结果与 Python **逐字节一致**，
> 由 `tests/test_m27_display_hosts.py` 对拍保证。`舍入()` 刻意用 half-up
> （金额的「四舍五入」），与 Python 侧同一约定。

## 为什么是「纯 JS 解释器」而非「ffi 加载 jsvm.dll」

路线图 M13.2 原文写的是「Node 用 ffi-napi 绑 jsvm.dll」。但调研后发现
jsvm.dll 是**宿主驱动**架构（不链接 libpython，全部 ~40 个语义回调都要宿主实现），
ffi 方案需要把 `runtime.py` 的语义整个翻译成 JS，工作量更大、更易错。

而 JSON 字节码是纯数据（常量池只含标量），JS 直接解释它只需翻译指令分发 +
12 个内建 + 方法表，工作量约 1/3，且真正零依赖。这是更贴合「跨语言字节码分发」
本意的做法。
