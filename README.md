# 基石（jishi）

一门像 Python 一样简单易用的**中文编程语言**。

</div>

> **技术栈声明（公开透明）**
> - 前端（词法/语法/AST/中文报错）由 **Python 实现**
> - 三个执行器：**树遍历解释器**（默认，Python）/ **Python 字节码 VM** /
>   **C 字节码 VM**（`cvm/`，自研 C 栈式虚拟机，gcc 编成 DLL/SO，
>   纯计算场景提速最高 46x，wheel 内自带无需本机 gcc）
> - 通过桥接层**可调用任意 Python 库**，标准库为中文薄封装
> - 不 fork、不 patch CPython，也不宣称"完全自主"，以上技术栈如实标注
>
> 已是一条「拿到就能写」的完整通用语言：模块系统、面向对象、异常、包管理雏形、
> AI 原生工具链（语言卡 / 结构化报错 / 评测集）、沙箱 + MCP 集成、wheel 内带 C VM。
> 定位不是教学玩具，长期目标是可维护的开源项目。

## 安装

**Windows**：下载 `jishi-<版本>-windows-x64-setup.exe`，双击安装即可
（用户级安装、免管理员；简体中文向导，含开始菜单快捷方式、可选加入 PATH、
标准卸载程序）。

**Linux / macOS**：下载对应压缩包，解压后运行 `install.sh`：

```bash
tar -xzf jishi-<版本>-linux-x64.tar.gz
cd jishi-<版本>-linux-x64 && bash install.sh
```

**pip 安装**（需本机 Python 3.10+）：

```bash
pip install jishi
```

发行包下载见 [GitHub Releases](https://github.com/benxiaoniao/JISHI/releases)，
每个版本附 `SHA256SUMS` 便于校验完整性。

## 快速上手

```bash
# 运行一个 .jsh 文件
jishi examples/01_猜数字.jsh

# 交互式 REPL
jishi -i

# 查看 AST（调试用）
jishi examples/01_猜数字.jsh --ast
```

第一个程序 `你好.jsh`：

```
# 你好，基石
打印("你好，世界！")
令 名字 = 输入("你叫什么名字？")
打印("欢迎你，", 名字)
```

## 语言示例

```
# 猜数字小游戏（判断/循环/输入）
导入 随机
令 答案 = 随机.随机整数(1, 100)
循环 10 次：
    令 猜测 = 整数(输入("猜一个 1-100 的数："))
    如果 猜测 < 答案：
        打印("太小了")
    否则如果 猜测 > 答案：
        打印("太大了")
    否则：
        打印("猜对了！")
        中断
```

```
# 异常处理（M5a：尝试/捕获/最终/抛出）
函数 折扣价(原价, 折扣):
    如果 折扣 <= 0 或 折扣 > 1:
        抛出 值错误("折扣必须在 0 到 1 之间")
    返回 原价 * 折扣

尝试:
    打印(折扣价(100, 2))
捕获 值错误 为 e:          # 异常对象可读 e.消息 / e.类型
    打印("出错了：", e.消息)
```

```
# 面向对象（M5b：类/继承/新建）
类 动物:
    函数 初始化(自身, 名字):      # 「初始化」是构造方法
        自身.名字 = 名字           # 「自身」是实例本身
    函数 叫(自身):
        打印(自身.名字, "在叫")

类 猫 继承 动物:
    函数 叫(自身):                 # 覆盖基类方法
        打印(自身.名字, "喵喵")

令 咪咪 = 新建 猫("咪咪")
咪咪.叫()
```

### M34：D 档第一批 —— 模式匹配与枚举

路线图对 D 档的定调是「重特性，先写最小原型测投入产出比」。这一轮挑了
**模式匹配**和**枚举**做原型，两个都走通了**解析期脱糖**，于是
**三个执行器 + 两个跨语言宿主一行都不用改**。

```
匹配 分数：                      枚举 状态：
    情形 90：       → 优秀           待办 = "todo"
    情形 80, 85：   → 良好           完成 = "done"
    情形 如果 分数 >= 60： → 及格
    情形 其他：     → 继续努力      打印(状态.待办)   → 状态.待办
```

| 特性 | 脱糖成 | 改动量 |
|------|--------|--------|
| 模式匹配 | `__匹配_N__ = 待匹配值` + `如果/否则如果/否则` 链 | 只动 `parser.py` |
| 枚举 | `类 X：`（初始化/文本）+ `X.成员 = 新建 X(…)` + `X.全部 = […]` | 只动 `parser.py` |

两个设计点值得记：

- **待匹配值只求值一次**：`匹配 取下一个()：` 落到临时变量，不会因为分支多
  就跑多次（测试里锁住了）。
- **枚举成员是实例而不是裸值**：所以 `打印(颜色.红)` 给 `颜色.红`（靠 `文本()`
  方法），还能取 `.名字` / `.值`。若成员直接是 `1`，打印出来就是 `1`，
  枚举「用名字代替魔法数字」的意义就没了一半。

#### 加关键字撞掉了既有 API

`匹配` 一关键字化，两处立刻炸：标准库函数 **`正则.匹配`**（M33 刚写、
真实项目在用）解析不了；真实项目里的变量 **`匹配组`** 被「关键字粘连检查」
拦下。修法是两条**通用**措施，不是特例补丁：

1. **`.` 后面的属性名允许关键字**（属性名位置本来就没歧义）——
   以后加关键字不必再担心撞既有 API。变量名/参数名/字典键仍不许（与 Python 一致）。
2. `匹配` / `枚举` 加进**粘连检查的跳过表**——它们和 `用` / `是` 一样是
   常用词前缀（匹配组/匹配器、枚举值/枚举类），粘连提示是净损失。

#### 顺带撞出宿主侧三处既有缺陷

枚举脱糖要用「类体外给类设属性」，一写就撞出宿主本来就有的坑（都不是本轮引入）：

| 缺口 | 表现 | 修法 |
|---|---|---|
| Node / Rust 都**没有类变量**（M23.3 一直没同步） | `类 A：` 里写 `x = 1` 报「不能给「<类 A>」的属性「x」赋值」 | 补 `getAttr`/`setAttr` 的类分支——Python 的类变量本来就是靠 `SET_ATTR` 实现的，**字节码零改动** |
| Rust **`继续` 之后再也 `中断` 不了** | 报「中断/继续没有对应的循环」 | `dispatch_signal` 多弹了一次循环块（弹的动作归 `POP_BLOCK`） |
| Rust 的 **`类型()` 给错名字** | 实例给「对象」、类给「类」，而 Python 给 `A 实例`/`类 A` | 补齐 + 三侧统一绑定方法名（此前三个都不一样） |

第二条尤其隐蔽：**单支/两支 `如果` 里看不出来**，必须有「`继续` 过了还要用
循环」才暴露——`情形` 脱糖恰好生成了那种形状。

#### D 档其余的 ROI 结论

**生成器**（脱糖路线走不通：要状态机/协程，三执行器实现方式完全不同，
且三大真实项目一个都没用到——「读大文件不炸内存」已由文件按行迭代解决）、
**多继承**（要 C3 线性化 + 重新设计 `超()`，与「简单」的定位冲突）、
`全局`声明 / `删除`变量（成本低但需求弱）——**都先搁置**，理由写在
`docs/设计决策.md` 的 D26。

### M33：Rust 宿主的「零依赖标准库」

Rust 宿主原本只有 `数学`/`文本`/`随机` 三个标准库模块（而且函数不全），
这一轮补到 **14 个模块、约 130 个函数**，与 Python 侧同宽。
`Cargo.toml` 的 `[dependencies]` 仍然是空的——所以重活全是自己写的：

- **正则**：自写**回溯引擎**（字符类、量词与非贪婪、分组、`(?=)`/`(?!`、
  锚点、`\b`、反向引用）。Python 的 `re` / JS 的 `RegExp` 在零依赖下都用不了。
- **加密**：自写 md5 / sha1 / sha256 / sha512。算法规范很死（常数表都在标准里），
  自己写反而好对拍；拿 `hashlib` 当裁判，`abc`、空串这些公开向量**逐字节一致**。
- **压缩**：手拼 zip 容器（本地头 / 中央目录 / EOCD / CRC-32）。
  **打包写 `stored`（不压缩）**——零依赖下没有 DEFLATE 压缩器，而 `stored`
  在规范里本来就合法；**解压躲不掉**（别人打的包默认都是 deflate），
  所以 inflate 是完整实现的（三种块都支持）。测试还**双向互操作**：
  Python 打的 deflate 包 Rust 解得开，Rust 打的包 `zipfile.testzip()` 校验通过。
- **网络**：Windows 上绑 `winhttp.dll`（`extern "system"`，**系统库、不是 crate**）
  → **https 也能用**；其余平台裸 `TcpStream`（`http://` 可用，`https://`
  明确报错，绝不静默降级成明文）。

`日期`/`时间` 还要绕两处 std 没有的东西：**本地时区**（绑
`GetLocalTime` / `localtime_r`）与 **`strftime` 子集**（`%U`/`%W` 照 CPython 公式）。

#### 探针全绿之后，真实项目又撞出三块

14 个模块补完、113 例对拍 0 不一致之后，按 M30 定下的标准拿
`examples/projects/` 的真实项目跑 —— **又撞出三块**：

| 缺口 | 表现 |
|---|---|
| **`BUILD_SLICE`（切片）整条指令没有** | `排名[::-1]` 报「未知指令 48」（M30 只补了 Node） |
| **`输入()` 内建不存在** | 三个真实项目里两个要读标准输入 |
| **`列表.排序` 静默失效** | `Val::partial_cmp` 只处理数字与精确小数，字符串/列表返回 `None`，而排序把 `None` 当成「相等」→ **排了等于没排** |

第三条最隐蔽：**不报错、不错值，只是顺序不对**（成绩分析的总分排名全乱）。
顺带修了 `表格.排序按` 的倒序 —— Python 的 `sorted(..., reverse=True)`
对**并列项保持原顺序**，而「排完再整体反转」会把并列项也倒过来。

> **教训**：写完新模块一定要拿真实项目验一遍。「探针里没有的用例」
> 就是盲区（M30 的切片、M33 的排序都是这么撞出来的）。

#### 对拍还暴露了三处「跨宿主不一致」

Python 侧有几处在 Windows 上做**换行转换**，于是同一份程序在 Python 侧输出
CRLF、在 Node / Rust 宿主输出 LF：CLI 输出（`_setup_io` 显式 `newline="\n"`）、
`系统.执行`（改成按字节收再解码）、`json.读文件`/`写文件`（补 `newline=""`）。

另外两处「内部实现细节漏给用户」也修了：`正则.查找全部` 多分组时漏出 Python
的**元组**（基石没有元组类型，统一成列表）、`类型(表格)` 给 `_table` 类名
（加类型名钩子，三个宿主统一显示「表格」）。

### M32：核实「剩余边界」，把静默算错清零

`docs/embed.md` 里那份「剩余边界」清单，**逐条横向实测**了一遍——因为文档
会过时（上一轮就撞过：embed.md 给 JS 的成员测试标了 ✅，实际根本没实现）。
探测结果分三类，两类都动手了：

**一、两条过时描述（删掉）**

- 「JS 的 `1` 与 `1.0` 无法区分」——字节码里的小数常量本来就带 `t: "float"`
  标记，`decodeConst` 早就按它包成 `FloatBox` 了。
- 「JS 的错误渲染没有源码行」——M30 已规范化成中文。

**二、五处「静默算错」（修掉）**

| 现象 | 根因 | 对策 |
|---|---|---|
| `9223372036854775807` 显示成 `...776000`、`2 ** 64` 算错 | JS 的 number 是双精度 | 必要时切 `BigInt`（任一边是 BigInt，或结果超出安全范围）；字节码里超范围的 int 常量按**字符串**编码 |
| `9223372036854775807 + 1` 给 **负数** | Rust 的 `i64` 回绕 | 提到 `i128` + `checked_*`，到边界报错 |
| `2 ** 64` 给 **`0`** | **ctypes 边界静默截断**（C 侧已有溢出回落，是回落算完之后丢的） | `_jint` 里检查范围报错（`JVal` 的 16 字节布局不能动） |
| `打印(类)` 给 `[object Object]` | 那几个类没有 `toString` | 七个类补 `toString()`，一处定义三处生效 |
| 「加减乘超 28 位」三边给不同的数 | 只有 `div` 做了 context 舍入 | 补齐 `add/sub/mul` + 按 CPython 的 `__str__` 实现科学计数法 |

**三、两处明确报错（补上）**

- **Rust 的类型标注校验**：编译器早已把校验发射成函数的前导字节码
  （`检查实参`），Rust 侧没实现这个内建——带标注的函数直接报「找不到名字」。
- **Rust 的 `是`/`不是` 对类与函数**：创建时分配递增序号（`Clone` 跟着复制），
  等价于 Python 的 `id()`。绑定方法仍明确报错（Python 里 `a.方法 是 a.方法`
  为假，Rust 侧判会得真——宁可明确不支持）。

**顺带发现（未动，已如实记进 `docs/embed.md`）**：树遍历不支持类体里写
`通过`；JS 宿主没同步 M23 的「类变量」；类型标注表里的 `空`/`函数`
语法上写不出来（是关键字）。

### M31：JS 标准库补齐到与 Python 同宽

M30 把 JS 宿主补到「5 个常用模块」，这一轮把剩下 7 个补完：
**路径 / 文件 / 日期 / 时间 / 加密 / 压缩 / 网络**。补完的结果是
`examples/projects/` 里的**全部**项目都能在 JS 宿主上跑 —— 包括上一轮
还明确写着「跑不了」的「网页采集」。

三块各有各的坑，都是「照着 Python 写反而会错」的类型：

- **压缩**：Node **没有内置 zip**。`zlib.deflateRawSync` / `inflateRawSync`
  只管 deflate 流，本地文件头（30 字节）、中央目录项（46 字节）、EOCD
  （22 字节）、CRC-32 都得按 PKWARE 规范自己拼。所以这一块的测试**不只对拍
  输出**，还拿 Python 的 `zipfile` 当裁判：Node 打的 zip 要被 `zipfile` 读出来
  （`zf.testzip()` 校验 CRC），Python 打的 zip 要被 Node 解开 —— 双向都测。
- **网络**：Node 没有同步 HTTP —— `fetch` 是异步的，而基石没有 `await`，
  标准库不能变成异步函数。方案是 `spawnSync(process.execPath, ['-e', 脚本])`
  起一个**自身的子进程**跑异步请求，结果经 stdout 回传。零第三方依赖，
  也不要求系统装了 `curl`。代价是每次请求多一次进程启动（本机约 40ms），
  换来与 Python 侧 `urllib` 一样的**同步**调用形态。
- **日期时间**：JS 没有 `strftime`，`toLocaleString` 又依赖系统 locale，
  于是自己实现了一个子集（`%U`/`%W` 的周号照 CPython 的公式：新年第一个
  周日/周一之前的日期算第 0 周）。`时间.睡眠` 用 `Atomics.wait` 同步阻塞。

顺手改掉 Python 侧两个**跨平台不一致**：

1. **文件读写改成「换行保真」**：Python 的文本模式在 Windows 上会把 `\n`
   悄悄写成 `\r\n`，于是「同一份程序在两个平台产出的文件字节不同」，也与
   Node 的 `fs`（不转换）对不上。标准库统一显式 `newline=""` —— 基石的定位是
   「同一份程序到哪都一样」，那就得从字节层面保证。
2. **值→文本统一**：`文件.写文本` / `写行`、`加密.摘要` 之前走 Python 的
   `str()`，于是 `写文本(p, 真)` 写出的是 `True`（而 `文本(真)` 给 `真`）。
   改成 `jishi_repr`，与 M30 修的 `文本.拼接` / `格式化` 一致。

路径模块还有两个细节：`后缀` **不能直接用 `path.extname`**（pathlib 对 `a.`
与 `.bashrc` 都算无后缀，而 JS 给 `'.'`）；Windows 上 Python 的 `Path.__str__`
总吐 `\` 而 JS 的 `path` 保留输入里的分隔符，所以 `连接` / `父目录` 的返回值
要显式规范化。

### M30：JS（Node）宿主补齐到 Python 侧

Rust 补完补 JS。这次先写了个**横向探测脚本**：把 39 个用例在 Node 与
Python VM 上各跑一遍逐条比对，实测出 **37 处不一致**，再按实测范围补

### M29：Rust 宿主补齐到 Python 侧

把 Rust 宿主从「核心链路可跑」补到**与 Python 侧逐字节对拍一致**（剩下的

1. **用户方法调用**（`对象.方法()` / `初始化` / 继承覆写 / 递归方法）。

2. **列表高阶方法**：`映射` / `过滤` / `排序按` / `归约`。实现要点是

3. **集合 / 文件与上下文 / 精确小数**：集合（有序去重，11 个方法）、

- `execute` 收到 `Err(e)` 直接 `return Err(e)`，**绕过了异常分发**——于是

- `返回` 不跑 finally（缺 Python 侧的 `_return_via_finally`），所以

### M28：Rust 宿主修掉可变容器

上一版留了**一处「静默算错」**：Rust 侧 `列表.追加` 改的是副本，原变量不动、
推导式返回空列表 —— 不报错但结果是错的，比直接报错危险得多。

根因是 `Val::List(Vec<Val>)` 是**值类型**、`Clone` 是深拷贝。
改成 `Rc<RefCell<Vec<…>>>`（`Val::clone` 只复制指针）后，方法里的
`borrow_mut()` 就能改到共享数据，`令 b = a` 也成了真正的别名。

**一个容易漏的配套改动**：Rust 版把「列表自身」当迭代器（`iter_next` 会
`remove(0)`）。以前靠值拷贝侥幸正确，共享之后如果不显式快照，
`遍历 x 在 a` 会把 `a` **逐元素吃掉**。所以 `make_iterator` 与
`unpack_values` 都改成取快照——`test_rust_iteration_does_not_consume`
专门锁这一点。

顺带补齐 Rust 侧**完全没实现**的两种比较运算（写「按首字母分组」这个真实
惯用法时才撞出来）：

```python
如果 k 在 分组：         # 成员测试：列表按值、字典按键、文本找子串
打印(p 是 q)             # 同一性：数字文本按值，列表字典按身份
```

类/实例/函数的 `是`/`不是` **明确报错**而不是猜：它们在 Rust 里是值类型、
没有身份可谈，硬按「同内容即同一」算会给出和 Python 相反的答案——那又是一次
静默算错。

### M27 收尾：Rust 宿主首次真正跑起来

起因很小：`cargo` 命令「执行成功但什么都不做」。查下去发现
`~/.cargo/bin/` 下 13 个文件（`cargo.exe` / `rustc.exe` …）都是 **0 字节** ——
rustup 在 Windows 上把这些做成指向 `rustup.exe` 的硬链接，链接坏掉后退化成
空文件，执行它没有输出且 `rc=0`，**极像「命令被沙箱吞了」**（前两轮就是这么
记的，此处更正）。重建硬链接后 `cargo 1.98.1` 恢复正常。

第一次真正把 Rust 宿主跑起来，立刻抓到两个**阻塞级既有 bug**：

1. **`Flow::Return` 语义混淆 → 函数调用整个不可用**。它同时表示「本帧结束，
   请弹帧」和「刚压了新帧，别弹」，于是每次函数调用后新帧立刻被弹掉，
   外层去执行那个**还没拿到实参**的 `CALL`，`fn_base` 下溢 → panic。

2. **`MAKE_FUNCTION` 默认值对齐按全部形参算**，有 `*参数` 时错位
   （Python 侧在 M25 修过同一个坑，Rust 漏了）。

顺带更正一处**夸大表述**：Rust 宿主自 M13.3 起写着「最小可运行」，但
`tests/` 里只有 Node 的对拍、Rust 从没运行验证过 —— 第 1 个 bug 说明它
连函数调用都跑不了。现在补上 `tests/test_m27_rust_host.py`（21 对拍 +
5 xfail），`docs/embed.md` 的支持程度表也按**实测**重写。

**实测能力**：显示规则 / 变长参数 / 星号解包 / 函数 / 递归 / 闭包 / 匿名函数 /
默认参数 / 基础控制流 —— 全部与 Python 逐字节一致。

**⚠️ 一个「静默算错」**：**可变容器**（`列表.追加` 改的是副本，推导式因此
返回空）。根因是 Rust 的 `Val` 是值类型、`get_attr` 拷一份再改；修它要把
`List`/`Dict` 换成 `Rc<RefCell<…>>`。这条比「报错」严重（拿到错结果却不知道），
已在 `embed.md` 与测试的 xfail 里明确标出。

### M27 已交付：值→文本的统一

同一个值以前有两种写法：`打印(空)` 给 `None`、布尔给 `True`/`False`，
而 REPL 回显与 `类型()` 给中文「空/真/假」——用户得猜哪个算数。
根因是这件事有**两份**几乎一样的实现（`runtime.jishi_repr` 与

现在收敛成一处 `runtime.jishi_repr`，`打印`、`文本()`、字符串插值
`` `{值}` ``、容器内元素、REPL 回显全走它：

```python

打印([1, 真, 空, "甲"])        # [1, 真, 空, '甲']

打印(路径.存在("docs"))        # 真（桥接回来的原生 bool 也一样）

- 字典用半角 `: `，与源码 `{"甲": 1}` 写法一致，打印结果能直接抄回代码。
- 这三类字面值在文档、教程、示例、快照里**全部**跟着改到了中文。

  jishi 安装 数学工具        # 走默认索引：读索引 → 下载 → 校验和 → 安装
  jishi 列表
  ```

- **发布工具**：把本地包目录变成「能装的东西」。

  ```bash
  jishi 发布 我的包 --base-url https://…/下载 --index packages/索引.json
  jishi 索引 包集合目录 --base-url https://…/下载 --out-index packages/索引.json --checksum
  ```

  发布时会校验 `包.json`（必填字段、字段名拼错、版本格式），打包只收
  `包.json` 与 `.jsh`，并生成 sha256 供安装端校验。

- **钻石依赖冲突检测**：`jishi 检查` 把「谁以什么约束要求了它」讲清楚：

  ```
  包「共同」的版本要求互相打架（当前装的是 1.5.0）：
    · 甲 → 丙 → 共同 要求 >=2.0.0
    · 乙 → 共同 要求 <2.0.0
    建议：统一各上游对它的版本要求，或先卸载引起冲突的包
  ```

  只**报告**不自动求解——生态还小，把成因讲清楚比自动挑版本更有用。

### M20 已交付：性能优化（批量 JVal 转换）

用 benchmark + cProfile 定位到 C VM 的真正瓶颈：**每次迭代/调用的返回值都要

写入 C 侧数组，省掉逐个构造（实测转换快 ~9x，混合类型/大端自动回退逐个）。

|------|--------|--------|
| 整数循环累加 | 1.9x | **8.4x** |
| 函数调用密集 | 4.5x | **10.7x** |
| 算术混合运算 | 5.2x | **18.1x** |
| 列表构建与遍历 | 1.6x | **2.6x** |
| 递归斐波那契 | 18.3x | 18.1x |
| 当循环倒计数 | 44.4x | **45.9x** |

## 架构与数据流

```
源码 → tokenizer → parser → AST ──┬─→ Interpreter（树遍历，默认执行器）
                                  └─→ 编译器 → 字节码 ──┬─→ Python VM
                                                        └─→ C VM（jsvm.dll）
```

- 三个执行器（树遍历 / Python VM / C VM）共用 `jishi/runtime.py` 的语义，
  `tests/test_cvm.py` 对拍保证「换执行器不改变任何可观察行为」
  （stdout 与报错逐字节一致）。
- 默认仍走树遍历；`jishi/vm.py` / `jishi/cvm_bind.run_source_c` 可切换。
  性能：C VM 提速最高 46x（见 tools/benchmark.py，字符串拼接为架构边界）。
- **AI 原生能力**（M8/M9）架在 AST 与报错之上：`jishi/ai.py` 从
  tokenizer/parser/runtime/stdlib 动态收集元数据，产出语言卡、语言规格、
  JSON 结构化报错；`jishi/mcp_server.py` 把执行能力暴露给任意 MCP 宿主。

## 关键技术决策（详见 docs/设计决策.md）

- **D1 技术栈透明**：Python 前端 + C 内核 + Python 生态桥接，不 fork/patch CPython
- **D2 分词消歧**：关键字粘连检查只针对**多字关键字**（如果/循环/导入…），
  单字关键字（类/当/真/空/非/令）不做前缀检查，否则 `类型`/`当时`/`空间` 等日常词全被误伤。
- **D3 全角标点**：字符串与注释外做一对一归一化（`＝`→`=` 等）；全角空格 U+3000 在缩进中报错。
- **D4 执行模型**：树遍历 → 字节码 + C VM（M4），语法不变，对拍测试保证一致。
- **D5 标准库**：中文 API 是薄壳，绝不重造轮子，真实价值来自 Python 生态。
- **D7 对象方法分派**：方法表按类型分派返回闭包，列表方法原地修改、文本方法返回新值。
- **D8 REPL**：顶层表达式非空回显（真/假/空中文化）；空行强制结束多行块。
- **D11 异常对象模型（M5a）**：异常即 `JishiError` 实例，`e.消息`/`e.类型` 可读；
  捕获条件按类型名匹配，用 isinstance 判断（基类抓子类）。
- **D12 语法用中文助词（M5a）**：`捕获 值错误 为 e:`、`继承 基类:` 用「为/继承」
  等助词连接，不用冒号嵌套的类 Python 写法，读起来更像自然语言。

## 已踩过的坑（避免重踩）

1. `re.fullmatch` 对 `[...]` 单字符类多字符永远 False，要用 `[...]+` 运行正则。
2. dataclass 继承字段顺序 → 全部 `@dataclass(kw_only=True)`。
3. 全角引号需配对表（`“` 配 `”`），不是同字符闭合。
4. 块语句以 DEDENT 结束，parser 主循环不能要求 NEWLINE。
5. `与/或` 右操作数要用 `parse_expr(prec+1)` 而非 `parse_unary()`，否则比较运算符逃逸。
6. `dump_ast` 用 `vars()` 前先判类型（tuple/list 无 `__dict__`）。
7. Windows venv 路径 `Scripts/` 不是 `bin/`。
8. 尾随逗号：列表/字典/调用参数/函数参数四处循环都要支持（M2 已修）。
9. `数学.幂` 用 `math.pow` 返回 float，整数期望 int → 用 `**` 运算符。
10. `导入 文本` 会遮蔽内建 `文本()` 转换函数（与 Python 导入遮蔽一致，文档已注明）。
11. 调用括号内的 `名字 = 值` 一律按关键字参数处理（parser 调用上下文无赋值语义）。
12. `_lookup` 查英文 True/False/None 的提示要在"你是不是想写"建议**之前**抛出，
    否则编辑距离建议会给出误导性结果。
13. 三执行器共享 runtime 语义，但异常穿透调用栈的「重入边界」必须一致
    （vm.py 的 stop_at / C VM 的 stop_depth），否则类方法里 `抛出` 会被错误接住。
14. `非` 的优先级必须**低于比较运算**（M23 修正）。写成一元（最紧）会让
    `非 年龄 >= 18` 变成 `(非 年龄) >= 18` 恒为假——**静默给错答案**，
    项目教程自己就踩过。现按 Python `not` 语义：`非` 吃掉右边的比较表达式，
    吃不掉 `与/或`。
15. 新增比较运算码（`在`/`不在`/`是`/`不是`）要放在 **6–9**，不能占用 0–5：
    0–5 是 C VM 的 `compare_fast` 快路径，6 以上自动回落宿主回调
    `host->compare`——这是「加语义比较运算符零 C 改动」的前提（见 opcodes.CmpOp）。
16. C VM 里同一个函数每次跨边界都会新建 `CvmFunction` 包装，直接按 `id()`
    判断同一性会与另两个执行器结果相反（`f 是 g`）。修法是按 `JVal.v.u`
    （底层 `JsFunc*` 指针）缓存包装（见 `cvm_bind.CvmHost._func_cache`）。
17. 加比较类关键字（`不在`/`不是`）必须同时加进 tokenizer 的
    `_GLUE_CHECK_SKIP`：它们本身是常用词前缀，否则 `不在列表`、`不是我`
    这类正常变量名会被「关键字粘连」检查误报。

## 设计原则

1. **像 Python 一样简洁**：缩进划分代码块，语法零冗余。
2. **中文是母语**：报错信息全中文，精确到行列，附"你是不是想写…"修正建议。
3. **生态即生命**：绝不重造标准库，薄封装 Python 生态。
4. **透明不吹牛**：技术栈如实标注，走长期演进路线。
