# 接口汇总探针

状态：已毕业（M119 起绕道为 0）

「抓一个分页 JSON 接口 → 合并筛选 → 按客户汇总 → 导出 CSV/JSON」，另有一段
「从 HTML 里取商品表」和「提交 JSON 回执」。

这是 **M107「网络 + 结构化数据」**的量尺：只用手上的标准库写，写不顺手的地方
就是缺口。M107 之前它有 6 条绕道（请求头 / 提交 JSON / 状态码 / HTML 解析 /
字典↔表格 / 中文网址），**M107 之后消掉 5 条**，只剩下面这一条。

## 用法

```bash
# 终端 A：起样例站点（不联网、结果可复现）
python "examples/绕道探针/接口汇总/起样例站点.py" 8767

# 终端 B（在探针目录里跑，输出写当前目录）
jishi 汇总.jsh http://127.0.0.1:8767
```

样例站点故意设的门槛：接口要 `X-Token` 请求头（否则 401）、只认
`application/json` 的 POST（否则 415）、`/api/status/404` 返回 404 ——
这些在 M107 之前**全都是死路**，现在 `汇总.jsh` 一步不用绕。

📌 **M119 把最后一条（R101）也消掉了** —— 于是它不再是量尺，而是
「新能力怎么用」的示范：网址里**直接写中文**就行。

> 🤔 当初这条记着一条**反对意见**：「自动编码整段网址是错的（路径和查询串口径不同）」。
> M119 的做法把它化解了 —— **只转非 ASCII 字符（含空格），结构字符 `/ ? & = # %` 一律保留**。
> 因为 ASCII 部分一个字节都不动，路径与查询串的边界绝不会被改变；`%` 保留也保证
> 「已经编码过的网址」不会被二次编码。三边（Python `quote` / Rust 手写 / Node `encodeURI` 回退 `%25`）
> 逐字节一致。

## 用到的语言特性

- `网络`（获取 / 获取JSON / 提交JSON / 获取详情，**都带请求头**）
- `表格`（**从记录** 把 JSON 记录变成表 → `分组汇总` → `转记录`）
- `html`（**取表格** 从网页里提表，不再正则硬挖）
- `json`（写文件）、`编码`（url编码）

## 为什么值得有一份「Python 参考实现」

`参考实现.py` 只用 Python 标准库（`urllib` + `json` + `csv` + `html.parser`），
做同一件事 —— 它展示「这件事本来该多短」。两相对照，剩下的那 1 条绕道就是
基石还没长出来的部分。
