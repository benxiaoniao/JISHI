# 批量摘要（绕道探针）

用基石写的一个真实小工具：**对一批文件逐个算 SHA256**（批量处理里最常见的一种活）。

⚠️ 它属于 `examples/绕道探针/` —— **不是教学示例，是「量尺」**。
撞出来的每一处绕道都记在下面的清单里，由 `tools/detour_ledger.py` 汇总成
`docs/绕道台账.md`。

## 用法

```bash
jishi examples/绕道探针/并发批量/批量.jsh <目录> [后缀]
```

例：`jishi 批量.jsh 样本 .bin`（数据在**当前目录**下）。

## 它撞出了什么：**没有并发**

程序只能**一个个**算。这不是写法问题 —— 语言现在没有线程、进程、异步中的任何一个，
想「同时算几个」根本没有入口（见绕道 R005）。

那到底值多少？**我实测了**（`参考实现.py` 同一份逻辑，Python 侧 顺序 vs 线程池）：

| 场景 | 顺序 | 并发（线程池） | 结论 |
|---|---|---|---|
| 40 个 1 MB 文件（40 MB） | **0.087 秒** | **1.717 秒** | 并发**慢 20 倍** ❌ |
| 2000 个 4 KB 文件（8 MB） | **2.245 秒** | **0.814 秒** | 并发**快 2.76 倍** ✅ |

📌 **这个反例比正例更值钱**：并发**不是**「加了就更快」。
大文件顺序读本来就快，线程只是白白加了调度开销；真正的收益来自
**大量小文件的 IO 等待被重叠**。所以将来真要加（M111），
**得先写清「为哪类场景加」**，并且照这条探针的测法**先量再判** ——
量不出收益就别加（这正是 `AGENTS.md` 的准入三关）。
