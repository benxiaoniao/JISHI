# 批量摘要（绕道探针）

用基石写的一个真实小工具：**对一批文件逐个算 SHA256**（批量处理里最常见的一种活）。

状态：已毕业（M114 起绕道为 0）

⚠️ 它属于 `examples/绕道探针/` —— 原来是「量尺」：撞出来的每一处绕道都记在
下面的「绕道清单」里，由 `tools/detour_ledger.py` 汇总成 `docs/绕道台账.md`。

📌 **M114（`并发`）把它的绕道 R005 消掉了** —— 于是它不再是量尺，
而是「新能力怎么用」的示范。标记就是上面那行 `状态：已毕业`：判据两边都盯着
（没标的必须至少一条绕道，**标了的必须一条都没有**）。

## 用法

```bash
jishi examples/绕道探针/并发批量/批量.jsh <目录> [后缀]
```

例：`jishi 批量.jsh 样本 .bin`。**先造一批样本**（`造样本.py`）：

```bash
python examples/绕道探针/并发批量/造样本.py 样本 2000 4      # 2000 个 4 KB
python examples/绕道探针/并发批量/造样本.py 大样本 40 1024   # 40 个 1 MB
jishi examples/绕道探针/并发批量/批量.jsh 样本 .bin
```

程序会把**顺序**和**并发**两档都跑一遍，打印两档用时与加速倍数，
并核对「两档结果一致」。

## 它撞出了什么：**没有并发** → ✅ **M114 已解决**

程序当初只能**一个个**算：语言没有线程、进程、异步中的任何一个，
想「同时算几个」根本没有入口（绕道 **R005**）。

**M114 补上了 `并发.批量摘要(路径们)`** —— 一批文件的摘要同时算，
**结果顺序与输入严格一致**（所以并发不影响可复现性，五引擎仍能逐字节对拍）。

## 到底快多少（**实测，不声称**）

同一台机、同一份样本、热缓存下跑（Windows，4 核 8 线程）。**交错跑两轮取小值**
（照 `AGENTS.md` §1 那条：先量哪档会把它抬高）：

| 宿主 | 场景 | 顺序 | 并发 | 倍数 |
|---|---|---|---|---|
| **发行版（Rust）** | 2000 × 4 KB（8 MB） | 0.74 秒 | 0.37 秒 | **2.0 倍** ✅ |
| **发行版（Rust）** | 40 × 1 MB（40 MB） | 0.21 秒 | 0.05 秒 | **4.1 倍** ✅ |
| 判据基准（Python） | 2000 × 4 KB（8 MB） | 0.95 秒 | 0.44 秒 | **2.2 倍** ✅ |
| 判据基准（Python） | 40 × 1 MB（40 MB） | 0.058 秒 | 0.065 秒 | **0.89 倍**（略慢）❌ |

### 📌 两条要如实说的

1. **冷缓存那一轮不算数**：样本刚造出来第一次跑，发行版 2000 个小文件是
   **3.98 秒 → 0.37 秒（10.7 倍）**。那是把「等磁盘」也并行化了 ——
   第二次（进了系统缓存）就回到 2.0 倍。**报数字要报那一档可复现的**。
2. **大文件在发行版上反而快 4.1 倍，在 Python 侧却略慢** ——
   因为两边的**瓶颈不是一个东西**：判据基准用 OpenSSL 的 sha256（快），
   大文件由「顺序读」主导，并发的线程只是白加调度；
   而发行版的 sha256 是**自己手写的**（见 `rust/src/crypto.rs` 头注），
   40 MB 时**算摘要本身**就是瓶颈，多线程正好把它摊开。
   ⇒ 「并发值多少」**取决于瓶颈在哪**，不能一句话概括。

📌 **原来的那条反例仍然成立**：并发**不是**「加了就更快」。
大文件顺序读本来就快时，线程只是白白加调度与内存。所以
`并发` 模块的文档里反复写「大文件、纯计算不要用它」。
