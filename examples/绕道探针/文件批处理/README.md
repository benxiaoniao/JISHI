# 文件批处理探针

「把一个堆满下载文件的目录整理归档」：按模式找出报告 → 批量改名搬到 `归档/`
→ 原子写索引 → 暂存进临时目录 → 打包 → 递归删临时目录 → 自动打开索引。

这是 **M108「文件批处理 + 系统」** 的量尺：只用手上的标准库尽力写，写不顺手
的地方就是缺口。**M108 之前它有 6 条绕道**（按模式找 / 原子写 / 临时目录 /
递归删除 / 系统.打开 / 压 .gz），**M108 之后消掉 5 条**，只剩下面这一条。

## 用法

```bash
cd "examples/绕道探针/文件批处理"    # 在探针目录里跑，输出写当前目录
jishi 整理.jsh

# 想让它跑完自动打开索引，先设个开关（无图形界面的环境别开）
整理_自动打开=1 jishi 整理.jsh      # Windows: set 整理_自动打开=1
```

`样本/` 是准备好的输入：三个 `报告*.md`（其中 `旧报告.md` **不带**「报告」前缀，
用来验证模式匹配只挑对的）、一个 csv、两个 log、一个 `说明.txt`。
跑完在 `归档/` 里能看到改好名的报告、`索引.md`、`报告.zip`。

- [R206] 缺=压缩.压缩文件 位置=整理.jsh:76 | 想把几个 `.log`（或任何单个文件）
  压成 `日志.gz` —— 但 `压缩` 只有 **zip** 的 `打包` / `解压` / `列出内容`，
  没有「**单个文件 gzip**」这个入口。归档脚本里 `.gz` 是家常便饭（比 zip 轻、
  能独立解压、不少日志轮转工具直接产 `.gz`）；现在只能绕去 `系统.执行` 调
  `gzip`，而那个命令在 Windows 上不一定有。

## 用到的语言特性

- `路径`（**按模式找** / **临时目录** / **递归删除** + 连接 / 文件名 / 大小）
- `文件`（**原子写** + 创建目录 / 复制 / 读文本 / 写文本）
- `压缩`（打包 zip）、`系统`（**打开** + 环境变量）
- 别名导入（`导入 文本 为 文本库`——模块「文本」会遮蔽内建 `文本(...)`）
- f-string 插值、字符串拼接

## 为什么值得有一份「Python 参考实现」

`参考实现.py` 只用 Python 标准库（`glob` / `os.replace` / `tempfile` /
`shutil` / `webbrowser`），做同一件事。两相对照就知道「这件事本来该多短」
—— 差出来的那点，就是基石还没长出来的部分（现在只剩 gzip 那一条）。
