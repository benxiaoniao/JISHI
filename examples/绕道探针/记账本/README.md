# 记账本（绕道探针）

用基石写的一个真实小工具：**记一笔账、按类别汇总、按类别查**。

⚠️ 它属于 `examples/绕道探针/` —— **不是教学示例，是「量尺」**。
把日常真会写的程序用现有标准库**尽力写一遍**，看哪里必须绕道、哪里干脆写不出来。
撞出来的每一处都记在下面的「绕道清单」里，由 `tools/detour_ledger.py` 汇总成
`docs/绕道台账.md`（**台账从代码扫出来，不是手抄的**）。

## 用法

```bash
jishi examples/绕道探针/记账本/记账.jsh 记 25.5 餐饮 午饭
jishi examples/绕道探针/记账本/记账.jsh 记 100 交通 打车
jishi examples/绕道探针/记账本/记账.jsh 汇总
jishi examples/绕道探针/记账本/记账.jsh 查 餐饮
jishi examples/绕道探针/记账本/记账.jsh          # 不带参数 = 列出
```

数据存在**当前目录**的 `账目.json` 里（所以别在仓库根跑它）。

## 它跑起来什么样

```
$ jishi 记账.jsh 记 25.5 餐饮 午饭
已记：25.50 元 / 餐饮 / 午饭

$ jishi 记账.jsh 汇总
类别                合计
餐饮             25.50
交通            100.00
合计            125.50
```

⚠️ 上面那几行**对不齐** —— 三个汉字表头各差 2 列。见绕道 R003。

## 对照：Python 参考实现

`参考实现.py` 用标准库 `sqlite3` 做同一件事。行数更少，而且**数据量再大也不用
「每次把整本账读进内存」** —— 这就是它撞出来的那几条绕道值多少。

- [R001] 新增模块=数据库 位置=记账.jsh:41 | 「按类别汇总」：Python 一句 `GROUP BY` 就完了，这里只能把整本账读进内存、手写「有就加、没有就置」；账目一多，每次汇总都是 O(n) 全扫
- [R002] 新增模块=数据库 位置=记账.jsh:54 | 「按类别查」：没有索引，只能把全部账目逐条比字符串 —— 有十万笔账时和只有一笔时一样慢
- [R003] 增强=文本.左对齐 位置=记账.jsh:62 | 中文表格对不齐：`左对齐` 按**字符数**补空格，而一个汉字在等宽终端里占 **2 列**。实测 `文本.左对齐("中文", 8)` 得到「中文」+ 6 个空格（显示宽度 10，不是 8）
- [R004] 缺=文件.原子写 位置=记账.jsh:30 | 存账本直接覆盖写：写一半崩了（或断电）整本账就坏了。想「先写临时文件再改名」保平安，连临时文件名都得自己拼时间戳

## 顺带撞到的（**不进台账**）

写的时候还撞到一条**不属于「标准库缺什么」**的事：

`json.写文件(路径, 值, 缩进 = 2)` 这种**给标准库函数传关键字实参**，在
**Rust 树遍历**执行器上会直接报「还没实现」（`rust/src/walk.rs`：内建 / 标准库不接受
关键字实参，**有意明确报**、不静默丢）。而 Python 树遍历是接受的。

所以探针里改用了位置实参（`json.写文件(账本文件, 账目们, 2)`）。记在这儿，是因为：

1. 它是**执行器覆盖**的事，不是标准库缺口 —— 不该混进台账（台账只管「标准库缺什么」）；
2. 但它是**写真实程序才会撞到**的，而且会让 `tools/check_walk.py` 的「还没实现」那一列
   从 **0 变 1**（那条硬指标盯着）。

## 用到的语言特性

- `json` / `文件` / `系统` / `时间` 标准库
- 字典方法 `包含` / `键`、列表 `追加`
- 条件表达式（`参数们[3] 如果 长度(参数们) > 3 否则 ""`）
- `如果 / 否则如果 / 否则` 多分支、`尝试 / 捕获` 容错
