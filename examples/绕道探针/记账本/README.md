# 记账本（绕道探针）

用基石写的一个真实小工具：**记一笔账、按类别汇总、按类别查**。

状态：已毕业（M112 起绕道为 0）

⚠️ 它属于 `examples/绕道探针/` —— 原来是「量尺」：把日常真会写的程序用现有标准库
**尽力写一遍**，看哪里必须绕道、哪里干脆写不出来。撞出来的每一处都记在下面的
「绕道清单」里，由 `tools/detour_ledger.py` 汇总成 `docs/绕道台账.md`
（**台账从代码扫出来，不是手抄的**）。

📌 **M112（数据持久化）把它的两条绕道都消掉了** —— 于是它不再是量尺，
而是「新能力怎么用」的示范。标记就是上面那行 `状态：已毕业`：
台账会把它列进「已毕业的探针」，判据两边都盯着（没标的必须至少一条绕道，
**标了的必须一条都没有** —— 免得「已毕业」变成免检牌）。

## 用法

```bash
jishi examples/绕道探针/记账本/记账.jsh 记 25.5 餐饮 午饭
jishi examples/绕道探针/记账本/记账.jsh 记 100 交通 打车
jishi examples/绕道探针/记账本/记账.jsh 汇总
jishi examples/绕道探针/记账本/记账.jsh 查 餐饮
jishi examples/绕道探针/记账本/记账.jsh          # 不带参数 = 列出
```

数据存在**当前目录**的 `账目.db` 里（SQLite，所以别在仓库根跑它）。
**任何 SQLite 工具都能打开它**：

```bash
sqlite3 账目.db 'SELECT 类别, SUM(金额) FROM 账目 GROUP BY 类别'
```

### 从老账本搬过来（JSON → 库）

M112 之前这个探针只能把账目存在 `账目.json` 里。老的账本这样搬：

```bash
jishi examples/绕道探针/记账本/迁移.jsh [老账.json] [新账.db]
```

## 它跑起来什么样

```
$ jishi 记账.jsh 记 25.5 餐饮 午饭
已记：25.50 元 / 餐饮 / 午饭

$ jishi 记账.jsh 汇总
类别            合计
餐饮           25.50
合计           25.50
```

✅ 表头和数据是**对齐**的 —— M106 把 `文本.左对齐` 改成按**显示宽度**算
（一个汉字记 2 列）。改之前这几行是歪的，见下面「已消掉的绕道」。

## 对照：Python 参考实现

`参考实现.py` 用标准库 `sqlite3` 做同一件事。**现在两边都是 SQLite，而且用的是
同一个 schema**（`id / 金额 / 类别 / 备注 / 日期`）—— 所以**基石建的库，Python
那边能直接打开读写**，反过来也一样：

## 顺带撞到的（**不进台账**）

写的时候还撞到一条**不属于「标准库缺什么」**的事：

`json.写文件(路径, 值, 缩进 = 2)` 这种**给标准库函数传关键字实参**，在
**Rust 树遍历**执行器上会直接报「还没实现」（`rust/src/walk.rs`：内建 / 标准库不接受
关键字实参，**有意明确报**、不静默丢）。而 Python 树遍历是接受的。

所以探针里改用了位置实参（如 `json.转文本(账目们, 2)`）。记在这儿，是因为：

1. 它是**执行器覆盖**的事，不是标准库缺口 —— 不该混进台账（台账只管「标准库缺什么」）；
2. 但它是**写真实程序才会撞到**的，而且会让 `tools/check_walk.py` 的「还没实现」那一列
   从 **0 变 1**（那条硬指标盯着）。

## 用到的语言特性

- `数据库` / `系统` / `时间` / `文本` 标准库
- 字典取值（`各类[类名]["总和"]`）
- 条件表达式（`参数们[3] 如果 长度(参数们) > 3 否则 ""`）
- `如果 / 否则如果 / 否则` 多分支
