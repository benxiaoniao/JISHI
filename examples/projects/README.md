# M15.1 真实项目「反哺语言」记录

用基石写了 3 个真实项目后，发现的「写起来别扭」的语法点与改进建议。
这是语言收敛 1.0（M15.2）的重要输入。

## 三个真实项目

| 项目 | 目录 | 用到的特性 |
|------|------|-----------|
| CSV 成绩分析工具 | `examples/projects/成绩分析/` | 表格/文本/推导式/尝试捕获/输入 |
| 网页采集工具 | `examples/projects/网页采集/` | 网络/正则/表格/字典频次/插值 |
| 日志统计工具 | `examples/projects/日志统计/` | 文件/字典频次/排序/插值 |

## 发现的语法别扭点（按严重程度）

### 1. 无切片语法（高频痛点）

```jsh
排名 = 排名[::-1]   # ❌ 不支持，报「这里需要一个值，但看到了符号「:」」
排名 = 反转(排名)   # ✅ 当前唯一写法
```

**影响**：从 Python 迁移来的用户第一反应就是切片，`[::-1]`、`[1:]`、`[:-1]`
都是高频操作。当前只有 `反转()` 内建能覆盖「倒序」，但「取子列表」无等价物。

**建议**：M15.2 之后评估是否支持 `列表[起:止]` 切片（至少 `[::-1]` 反向下标
的解析优先级高于冒号）。成本：tokenizer/parser 的方括号处理要区分字典字面量
与切片。

### 2. `最小`/`最大` 只接受单列表

```jsh
最小(5, 长度(x))        # ❌ 报「_b_min() takes 1 positional argument」
[5, 长度(x)].最小值？    # 无此方法
```

**影响**：Python 的 `min(a, b)` 二参形式很常用（求两个值的较小者）。基石只能
`最小([a, b])`，多一层列表字面量。

**建议**：`最小`/`最大` 支持「多参数变长」（`最小(a, b, c)`）或「单个列表」两种
调用形态，与 Python 对齐。

### 3. `导入 文本` 遮蔽内建 `文本()`

```jsh
导入 文本          # 导入后，内建转换函数 文本(...) 被遮蔽
文本("123")        # ❌ 报「模块文本不能直接调用」
```

**影响**：`文本` 既是标准库模块名，又是内建类型转换函数，导入即冲突。
这是 Python `str` 也有类似问题的中文放大版（模块名直接叫「文本」）。

**建议**：已在语言规格标注此遮蔽（与 Python 导入遮蔽一致），但应在
「导入 文本」时给出更友好的提示，或考虑标准库改名（如「文本处理」）。
**暂维持现状**（改名是 breaking change，留待 1.0 后）。

### 4. 正则模式含双引号时的定界符选择

```jsh
令 模式 = "<a[^>]+href="([^"]+)"[^>]*>"   # ❌ 双引号嵌套冲突
令 模式 = "<a[^>]+href="([^"]+)"[^>]*>"   # 需用中文引号包裹
```

**影响**：正则里常含 `"`，用英文双引号包裹会冲突。基石支持中文引号作
字符串定界符（D3），但用户未必知道。

**建议**：教程/语言卡补充「正则模式推荐用中文引号包裹」的提示。

### 5. 命令行参数（argv）缺失

三个项目都用 `输入()` 交互读路径，无法 `jishi 脚本.jsh 参数1 参数2` 传参。

**影响**：真实 CLI 工具通常需要命令行参数，交互式输入在脚本化场景不便。

**建议**：评估是否引入 `参数` 内建（读取 argv），或 `jishi 脚本.jsh -- 参数`。
**留待 M16 或之后**（发行版会顺带解决入口传参）。

## 反哺结论

- 1、2 是**高频且成本可控**的语法增强，值得在 1.0 前评估；
- 3、4 是**文档/提示**层面的问题，无需改语法；
- 5 是**发行版（M16）** 的自然延伸，随入口传参一起解决。
