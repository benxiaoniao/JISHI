# 图片格式转换 —— 基石的第一个第三方包

把图片在 **BMP / PPM / PGM / PNG** 之间转来转去，**纯基石实现，不调用任何外部程序**
（不需要先装 ffmpeg / ImageMagick）。

> 📌 **名字为什么改了**：原来叫「图片」，太泛 —— 一看还以为是「显示图片 / 处理像素」
> 的通用库。它实际只干一件事：**格式转换**。现在叫「图片格式转换」，一看就知道边界。

```jishi
导入 图片格式转换 从 本地包

图片格式转换.转("照片.bmp", "照片.png")          # 一步到位：读进来、写出去
令 图 = 图片格式转换.读("照片.bmp")              # {宽, 高, 像素, 来源格式}
打印(图片格式转换.尺寸(图))
打印(图片格式转换.取像素(图, 0, 0))              # [红, 绿, 蓝]
图片格式转换.设像素(图, 0, 0, [255, 255, 255])
图片格式转换.写(图, "改过.bmp")
```

## 装

```bash
jishi 安装 图片格式转换 --local-dir examples/packages/图片格式转换   # 从目录装
jishi 安装 图片格式转换                                              # 从索引源装（已发布）
```

装完 `导入 图片格式转换 从 本地包` 就能用 —— **0.2.9 起产品版（单二进制）也一样**：
导入在编译期展开成函数调用，Python / C VM / Node / Rust 五个引擎跑同一份字节码。

## 能做什么

| 格式 | 读 | 写 | 说明 |
|---|---|---|---|
| BMP | ✅ | ✅ | 24 位读写；32 位（BGRA）只读、丢掉 alpha；**带调色板的 8 位不支持**（会明确报错） |
| PPM | ✅ | ✅ | P6 二进制、最大值 255 |
| PGM | ✅ | — | P5 二进制灰度，读进来**摊成三通道**（r=g=b） |
| PNG | ❌ | ✅ | 写 8 位真彩色；**读不了**（见下） |

其它接口：`空图(宽, 高, 底色)` · `取像素` / `设像素` / `填充` · `尺寸` · `支持格式()`。
完整接口表在[站点包页](https://xn--3jsy75e.cn/packages.html)（从源码自动扫出来的）。

## 已知边界（如实写，不粉饰）

1. 🔴 **PNG 只能写、不能读。** 读 PNG 要自己实现 inflate（fixed/dynamic Huffman 解码），
   那是另一个量级的工作。遇到 `.png` 会**明说**「只写不读、要读先转成 BMP/PPM」，
   而不是甩一句「出错了」。
2. 🔴 **写出的 PNG 不压缩**（deflate 的 stored 块）。好处是不用实现 LZ77+Huffman 就能合法；
   代价是**文件跟 BMP 一样大**：128×128 的图 PNG 49,348 字节、BMP 49,206 字节。
3. **性能**（Python 参考实现，本机实测三档，不是估的）：

   | 尺寸 | 造像素 | 写 BMP | 写 PNG |
   |---|---|---|---|
   | 32×32 | 66 毫秒 | 59 毫秒 | 202 毫秒 |
   | 64×64 | 274 毫秒 | 226 毫秒 | 730 毫秒 |
   | 128×128 | 1,230 毫秒 | 988 毫秒 | 3,607 毫秒 |

   大致线性 ⇒ **百万像素要几分钟**。定位是「小图 / 图标 / 教学与格式验证」，
   不是「批量处理照片」。

## 这个包撞出来的三个缺口（这是它最大的价值）

写这个包不是为了「有个包」，是为了**逼出包管理的真问题**：

1. ✅ **产品版导入不了包**（最硬的一条，0.2.9 已修）。以前 `jishi-rs` 能 `安装`，
   但 `导入 图片格式转换 从 本地包` 直接报「Rust 引擎不支持」——
   **装得上、用不了**。现在本地包在**编译期展开**成函数调用，
   五引擎（Python 树遍历 / Python VM / C VM / Node / Rust）逐字节一致。
2. ⏳ **`字节` 没有「列表 → 字节」的构造器**。源码里造字节只能
   `编码.十六进制解码("89504E47")` 这样**攒十六进制文本**再解回来。
   本包为此写了层 `_成字节()`（256 项查表），能用但绕。
   **暂缓**：按「真实需求驱动」，等第二个包也这么写再做。
3. ✅ **`包.json` 表达不了「要求基石版本」**（0.2.9 已加）。现在可以写
   `"基石版本": ">=0.2.9"`，不满足时安装会被拦下并给 `E4010`（修法是 `jishi 升级`）。

三条的来龙去脉记在 `docs/包管理与后续路径规划.md`。
