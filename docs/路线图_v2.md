# 基石语言路线图 v2（M35 起）

> 上一版规划见 [`技术路线_v1.0之后.md`](技术路线_v1.0之后.md)——那里面
> **M17–M34 的详细论证与实测记录**仍然有效，是本文的事实来源；本文只回答
> 一个问题：**M35 之后往哪走**。
>
> 写于 2026-09-13（M35 收尾时）。

---

## 〇、一句话

M0–M34 已经把「语言核心 / 三执行器 / 两跨语言宿主 / 工具链 / 三平台发行」
打通，语法面也基本铺满。**从 M35 起，主线从「扩语法」转为
「收敛 + 可信工具链 + 真实项目验证」**——不是没得做，而是**继续猛加语法的
边际收益已经低于它的代价**。

---

## 一、为什么转向（事实基础，不拍脑袋）

### 1.1 探针实测：语法缺口只剩 9 项

`tools/probe_capabilities.py` 当前 **39/48 可用**（M23 前是 9/38）。剩下的
9 项不是「还没轮到」，而是需要**逐条判定**的（见 1.2）。

### 1.2 剩余 9 项的逐条判定

| 探针项 | 判定 | 理由 / 替代方案 |
|--------|------|----------------|
| 三元表达式 | **做**（M36，走脱糖） | 高频；可脱糖成「匿名函数立即调用」，三执行器零改动。**唯一要定的是中文语序**。 |
| 位运算 `& \| ^` | **不做语法，改内建** | 日常业务代码罕见（多用于标志位/哈希/底层）。给 `位与()`/`位或()`/`位异或()`，零语法成本（关 0）。 |
| 位移 `<< >>` | **不做语法，改内建** | 同上：`左移()`/`右移()`。 |
| 元组 `( … )` | **暂缓** | 它唯一不可替代的价值是「不可变 + 可哈希当字典键」；而「列表当键」已能跑。且要新增容器类型 → **C VM 得动 `JVal` 的 16 字节布局**，成本与收益不成比例。先给 `冻结(列表)`（只读视图）顶一顶。 |
| 字典合并 `\|` | **不做语法，加方法** | `字典.合并(别的)` 已够用；省下的 `\|` 留给将来可能的集合运算语义。 |
| 多继承 | **不做** | 要 C3 线性化 + 重做 `超()`（M23.4 的脱糖建立在单继承上）。单继承 + 组合够用。（设计决策 D26） |
| `全局` 声明 | **不做** | 需求弱；闭包与参数传递已能表达。 |
| `删除` 变量 | **不做** | 需求弱。显式让变量离开作用域的需求，用函数边界表达更清楚。 |
| 生成器 `产出` | **搁置** | 脱糖走不通（要状态机/协程，三执行器实现方式完全不同，C 侧还要动 `JVal`）；三个真实项目**一个都没用到**惰性序列，「读大文件不炸内存」已由文件按行迭代解决。（D26） |

> **判定原则**：能用内建/标准库解决的，不动语法（关 0）。上表 9 项里
> **只有 1 项真的需要新语法**（三元表达式），其余 8 项要么有零成本替代、
> 要么明确不做。这本身就是「语法面已收敛」的证据。

### 1.3 M34 留下的另一半教训

**脱糖是廉价路，但只对「既有语句的组合」有效。** 模式匹配、枚举走通了
（解析器一两百行，三执行器 + 两宿主零改动）；生成器与多继承走不通，
成本立刻回到「三执行器各写一遍」的量级。所以**任何新语法到手，
第一问问「它能写成既有语句的组合吗」**，答不上来就先别动。

## 二、M35 起的路线（三条主线）

### 主线 A：语言面的最后收敛——把探针做成「无悬案」

**目标**：探针的 48 项**每一项都有明确结论**（做 / 有替代 / 不做），
不再有「待定」；新增的每一项都配三执行器对拍。做完即可宣布
**语法冻结（semantic freeze）**，进入 1.0 语义稳定期。

| 编号 | 内容 | 成本 | 关 0 判定 |
|------|------|------|-----------|
| A1 | 三元表达式（脱糖） | 低（解析器） | 走脱糖 |
| A2 | 位运算/位移内建（`位与` 等 5 个函数） | 极低（内建） | ✅ 无语法 |
| A3 | `字典.合并()` 方法 | 极低（内建） | ✅ 无语法 |
| A4 | `冻结(列表)` 只读视图（元组的轻量替代） | 低（内建/标准库） | ✅ 无语法 |
| A5 | 探针改造：9 项各自标「已做 / 有替代 / 不做 + 理由」 | 极低 | — |

**验收**：`probe_capabilities.py` 输出无「待定」；A1 有三执行器 + 两宿主
五路对拍；A2–A4 有测试但无需对拍（纯宿主侧内建，跨宿主按需同步）。

### 主线 B：可信赖的工具链（服务「出问题能快速定位」）

北极星里的后半句「**出问题能快速定位**」目前还有明显欠账——
M17 补了报错与调用栈，但**还没有调试器**。这一线优先级仅次于主线 A。

| 编号 | 内容 | 说明 |
|------|------|------|
| B1 | **调试器（最小可用）** | 断点 / 单步 / 看变量 / 看调用栈。**先树遍历**（纯 Python，最快见效），再推广到 Python VM；C VM 最后（要宿主回调传帧，成本最高）。 |
| B2 | LSP 增量同步 | 当前是整文件重解析，大文件下有卡顿；增量可显著改善编辑体验。 |
| B3 | REPL 增强 | 历史记录、多行编辑、Tab 补全（现状见 `jishi/repl.py`）。 |
| B4 | 格式化器打磨 | 已能用（`jishi/formatter.py`），补边界用例。 |

**验收**：能现场演示「在一个几十行的程序里设断点、单步、看到调用栈、
定位到出错那一行」；B2 有「大文件编辑不卡」的量化对比。

### 主线 C：让真实项目说话（反哺 A / B）

**这一线不是「顺便」，而是路线的事实来源**——M23 之后每一个真缺口
都是从写真实程序时撞出来的（上下文管理器、数据流水线、文件按行迭代…）。

| 编号 | 内容 |
|------|------|
| C1 | 把 `examples/projects/` 从 3 个扩到覆盖 5 类场景：数据处理 / 网页采集 / CLI 工具 / 教学演示 / 算法练习 |
| C2 | 每个项目维护一份「**别扭点清单**」：哪里写得绕、哪里报错看不懂、哪里要绕道 Python |
| C3 | 别扭点 → 归类进主线 A（语法）/ B（工具）/ 或「明确不做」 |

**度量**：同一程序的「基石版行数 vs Python 版行数」——**越短说明越
「方便实现意图」**；这是本项目核心定位的硬指标（不是自嗨指标）。

### 辅助线：AI 友好（带着走，不卡点）

- 每修一个语法点，同步补评测题与语言卡 / few-shot；
- 「容错解析」继续作为常设能力（遇到高频英文写法就补）；
- **有 API key / 预算时**跑一次真实模型评测，作为对外材料，但不作路线卡点。

## 三、明确「不做」的事（克制清单）

沿用上一版并补充本轮结论：

| 不做 | 理由 |
|------|------|
| 位运算 / 位移**语法** | 日常罕见，用内建替代（关 0） |
| 元组类型 | 需求弱，且要动 C VM 的 `JVal` 布局 |
| 多继承 | C3 线性化 + 重做 `超()`，单继承够用 |
| `全局` 声明 / `删除` 变量 | 需求弱 |
| 生成器 `产出` | 脱糖走不通，真实项目未用到（D26） |
| JIT / AOT 编译 | 已有 C VM，教学与工具场景性能足够 |
| 自研垃圾回收 | Python 前端已有 GC，ROI 极低 |
| 多线程 / 异步 | 严重破坏简单性，GIL 限制难绕过 |
| 宏系统 | 中文受众不需要元编程复杂度 |
| 复刻 Python 全部标准库 | `导入 x 从 python` 已兜底（D5） |
| 追求「完全自主」 | 木兰的教训；D1 已定：技术栈透明，不 fork/patch CPython |

## 四、度量体系（防自嗨）

| 指标 | 定义 | 现状（M35） | 目标 |
|------|------|------------|------|
| **探针可用率 / 无悬案率** | `probe_capabilities.py` 中「已做或已判定」的占比 | 39/48 可用 | **48/48 有结论**（主线 A 的验收） |
| **真实项目行数比** | 基石版行数 ÷ Python 版行数（取三个项目平均） | 未度量（M36 建立基线） | 逐档下降 |
| **报错可定位率** | 报错含行列 + 中文说明的比例 | M17 后 100%（缺口已补全） | 保持 100% |
| **调试可见性** | 能否在断点处看到变量与调用栈 | 无（**未度量即「无」**） | 主线 B1 交付后为「有」 |
| **对拍覆盖** | 三执行器 / 跨宿主的逐字节对拍用例数 | 见 README「测试」节 | 随特性同步增长 |
| **全量测试** | `python -m pytest tests/` | M35 后见 README | 全绿，不许留红 |

**纪律**（不变）：未度量的一律标「未度量」，不用估计值充数；
不利数据照实公布；说不清「怎么算完成」就不开工。

## 五、风险与诚实边界

| 风险 | 说明 | 应对 |
|------|------|------|
| 调试器跨三执行器工作量大 | C VM 要宿主回调传帧 | 分阶段：树遍历 → Python VM → C VM，每阶段可独立交付 |
| 真实项目投入产出不确定 | 业余时间写项目未必撞到「值得改语言」的点 | 项目选**自己真要用的**，避免为写而写 |
| 语法冻结后被现实打脸 | 冻结后仍可能出现必须加语法的新需求 | 冻结是「默认不加」，不是「永不加」；新需求仍走准入三关 + 关 0 |
| 特性蔓延破坏「简单」 | 见上 | 准入三关 + 第三节「不做清单」 |
| 杀软误报 | PyInstaller 产物常见 | 已有 wheel / 源码途径，不承诺绝对不报毒 |

## 六、遗留项清单（逐条结论，M35 整理）

「之前没有做完的」按下面逐条处理；**没有一条是含糊搁置**。

| 遗留项 | 结论 |
|--------|------|
| 短字符串内联（性能） | **暂不做**。当前 C VM 性能已达标（见 README 性能节）；没有实测瓶颈就不优化（M20 的教训：先测再改）。 |
| 调试器 | **做** → 主线 B1。 |
| LSP 增量同步 | **做** → 主线 B2。 |
| JS 宿主 `网络` 是子进程封装 | **保持**。是明确边界不是 bug，已在 `docs/embed.md` 如实标注。 |
| Rust 宿主若干边界（整数到 i128、`**` 只支持整数指数、`压缩.打包` 写 stored、非 Windows 无 `https://`） | **保持**。都是「明确报错」而非静默算错；唯一事实源是 `docs/embed.md`。 |
| 「本机 cargo 无法运行」的旧记录 | **已核实为过时**：cargo 1.98.1 可用（M27 修好硬链接后即正常），M34 的 Rust 改动已实际编译并对拍。本轮已从各文档更正。 |
| 树遍历类体不支持 `通过` | **已修**（M35）。根因是误判——`通过` 从来不是关键字，空块写法是单独一行 `:`；现三执行器统一在**解析期**校验类体。 |
| Node / Rust 缺类变量 | **已修**（M34）。 |
| 测试临时文件固定名（曾造成三次假失败） | **已修**（M35）。文件名带进程号，并行跑不再互相覆写。 |

## 七、推进顺序（一句话版）

```
M35  发布前验证 + 语言图标进安装包 + 打 tag 发三平台 Release + 遗留收尾 + 本路线图  ✅
  ↓
M36  主线 A 收尾：三元表达式（脱糖）+ 位运算/字典合并/冻结 内建替代
     → 探针 48/48 有结论 → 宣布语法冻结
  ↓
M37  主线 B1：调试器最小可用（树遍历）
  ↓
M38  主线 C：真实项目扩到 5 类场景，建立「行数比」基线
  ↓
（B2 LSP 增量 / B3 REPL 增强 / B4 格式化器 按需穿插）
  ↓
AI 友好：随主线自然生长，有机会再跑真实评测
```

**如果只做一件事（M36）**：把探针做成「无悬案」——不是为了数字好看，
而是**逼自己给每个缺口一个明确态度**。悬着的缺口会变成「用户以为有、
其实没有」的陷阱；判定清楚之后，语法面就能安心冻结，精力全部转到
工具链与真实项目上。
