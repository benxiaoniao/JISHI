## 〇、北极星与定位

- **定位**：一门**中文编程语言**，对标 Python 的易用性。
- **北极星（2026-09 调整后）**：**健全语言自身能力，让编程者方便地实现意图、
  出问题能快速定位**。「AI 友好」由主线降为辅助线（带着走，不卡点）。
- **三条长期铁律**：诚实不吹牛（未度量就写「未度量」）／三执行器语义必须一致／
  能用内建或标准库解决的就不碰语法。

## 二、准入标准（新特性开工前必须过）

**关 0（前置）——三执行器成本**：每个**语法特性**都要在树遍历 / Python VM /
C VM 三处实现并对拍，成本是「标准库函数」的一个量级。所以：**能用内建或标准库
实现的，不碰语法**。

关 1 真实需求（有真实项目或真实用户场景撞到）→ 关 2 可度量验收（说不出
「怎么算完成」就不开工）→ 关 3 投入产出比。

**加分项：解析期脱糖**。新语法若能表达成既有语句的组合，就在 parser 里脱糖
（已用五次：`超()`、集合字面量、`用 … 为`、模式匹配、枚举）——三执行器与
两宿主零改动，行为必然一致。**新语法到手第一问：「它能写成既有语句的组合吗？」**

## 三、当前规划：M36 起

### 3.1 事实基础：探针只剩 9 项，且已逐条判定

`tools/probe_capabilities.py` 当前 **50 项 / 可用 41 / 缺口 9**，且缺口
**全部已判定**（探针自己的汇总行会打印「无悬案」；有未判定项时退出码为 1）。
剩下 9 项不是「还没轮到」，而是**已逐条给出结论**的：

| 探针项 | 判定 | 理由 / 替代 |
|--------|------|------------|
| 三元表达式 | **已做** | ✅ M36 落地为 `甲 如果 条件 否则 乙`（与 Python 同语序，**零新增关键字**；脱糖成匿名函数立即调用，三执行器 + 两宿主零改动）。 |
| 位运算 `& \| ^` | **已做（改内建）** | ✅ M36 已提供 `位与()`/`位或()`/`位异或()`/`位取反()`。 |
| 位移 `<< >>` | **已做（改内建）** | ✅ M36 已提供 `左移()`/`右移()`（位数上限 1000000）。 |
| 元组 `( … )` | **暂缓** | 唯一不可替代的价值是「不可变 + 可当字典键」，需求弱；且要新增容器类型 → **C VM 得动 `JVal` 布局**，成本与收益不成比例。先给 `冻结(列表)` 顶一顶。 |
| 字典合并 `\|` | **已做（加方法）** | ✅ M36 已提供 `字典.合并(别的)`（返回新字典）。 |
| 多继承 | **不做** | 要 C3 线性化 + 重做 `超()`；单继承 + 组合够用（D26）。 |
| `全局` 声明 | **不做** | 需求弱；闭包与参数传递已能表达。 |
| `删除` 变量 | **不做** | 需求弱；用函数边界表达更清楚。 |
| 生成器 `产出` | **搁置** | 脱糖走不通（要状态机/协程，C 侧还要动 `JVal`）；三个真实项目一个都没用到惰性序列（D26）。 |

> 9 项里**只有 1 项真需要新语法**——这本身就是「语法面已收敛」的证据。

### 3.2 主线 A：语言面最后收敛 —— 把探针做成「无悬案」

**目标**：每一项都有明确结论（做 / 有替代 / 不做），然后**宣布语法冻结**。

> **✅ M36 已达成：语法冻结（2026-09-14）。** 探针 50 项全部有结论；
> 唯一新增的语法是条件表达式，且走的是零执行器改动的脱糖路线。
> 此后新特性默认先问「能不能用内建或标准库」，动语法要走准入三关。

| 编号 | 内容 | 成本 | 关 0 |
|------|------|------|------|
| A1 | 三元表达式（脱糖） | 低（解析器） | ✅ **已完成**：`甲 如果 条件 否则 乙`，只动 parser |
| A2 | 位运算 / 位移内建（**6 个函数**） | 极低（内建） | ✅ **全部完成**（Python 三执行器 + Node + Rust 五路对拍） |
| A3 | `字典.合并()` | 极低（内建） | ✅ **全部完成**；顺手补上 Rust 侧一直缺的 `字典.更新/弹出` |
| A4 | ~~`冻结(列表)`~~ **不做** | — | 复核后判定：真「只读」要新增值类型（要动三执行器 + C 的 `JVal` 布局），**成本不低**；而「可当字典键」这一条列表已满足 → 不做 |
| A5 | 探针改造：每项都带「结论」（已做 / 有替代 / 不做 + 理由） | 极低 | ✅ **已完成**（探针新增 `VERDICT` 表与「无悬案」判据） |

### 3.3 主线 B：可信赖的工具链（服务「出问题能快速定位」）

M17 补了报错与调用栈，但**还没有调试器**——北极星的后半句仍有明显欠账。

| 编号 | 内容 | 说明 |
|------|------|------|
| B1 | **调试器（最小可用）** | 断点 / 单步 / 看变量 / 看调用栈。**先树遍历**（纯 Python，最快见效），再推广到 Python VM，C VM 最后（要宿主回调传帧）。 |
| B2 | LSP 增量同步 | 当前整文件重解析，大文件有卡顿。 |
| B3 | REPL 增强 | 历史、多行编辑、Tab 补全。 |
| B4 | 格式化器打磨 | 补边界用例。 |

**验收**：能现场演示「在几十行程序里设断点、单步、看到调用栈、定位到出错行」。

### 3.4 主线 C：让真实项目说话（反哺 A / B）

M23 之后每一个真缺口都是从写真实程序时撞出来的（上下文管理器、数据流水线、
文件按行迭代…），所以这条线是**路线的事实来源**，不是「顺便」。

| 编号 | 内容 |
|------|------|
| C1 | `examples/projects/` 从 3 个扩到覆盖 5 类场景：数据处理 / 网页采集 / CLI 工具 / 教学演示 / 算法练习 |
| C2 | 每个项目维护「**别扭点清单**」：哪里写得绕、哪里报错看不懂、哪里要绕道 Python |
| C3 | 别扭点 → 归类进主线 A（语法）/ B（工具）/ 或「明确不做」 |

**度量**：同一程序的「基石版行数 ÷ Python 版行数」——越短说明越
「方便实现意图」。

### 3.5 辅助线：AI 友好（带着走，不卡点）

每修一个语法点同步补评测题与语言卡/few-shot；容错解析常设；
有 API key / 预算时跑一次真实模型评测作为对外材料，但不作路线卡点。

## 四、明确「不做」的事（克制清单）

| 不做 | 理由 |
|------|------|
| 位运算 / 位移**语法** | 日常罕见，用内建替代（关 0） |
| 元组类型 | 需求弱，且要动 C VM 的 `JVal` 布局 |
| 多继承 | C3 线性化 + 重做 `超()`，单继承够用 |
| `全局` 声明 / `删除` 变量 | 需求弱 |
| 生成器 `产出` | 脱糖走不通，真实项目未用到（D26） |
| JIT / AOT 编译 | 已有 C VM，教学与工具场景性能足够 |
| 自研垃圾回收 | Python 前端已有 GC，ROI 极低 |
| 多线程 / 异步 | 严重破坏简单性，GIL 限制难绕过 |
| 宏系统 | 中文受众不需要元编程复杂度 |
| 复刻 Python 全部标准库 | `导入 x 从 python` 已兜底（D5） |
| 追求「完全自主」 | 木兰的教训；D1 已定：技术栈透明，不 fork/patch CPython |
| 完整静态类型系统 | 与「简单易用」定位冲突；用可选标注做轻量替代 |

## 六、风险与诚实边界

| 风险 | 说明 | 应对 |
|------|------|------|
| 调试器跨三执行器工作量大 | C VM 要宿主回调传帧 | 分阶段：树遍历 → Python VM → C VM，每阶段可独立交付 |
| 真实项目投入产出不确定 | 业余时间写项目未必撞到「值得改语言」的点 | 项目选**自己真要用的**，不为写而写 |
| 语法冻结后被现实打脸 | 冻结后仍可能出现必须加语法的新需求 | 冻结是「默认不加」不是「永不加」；新需求仍走准入三关 + 关 0 |
| 特性蔓延破坏「简单」 | 见第四节 | 准入三关 + 不做清单 |
| 三平台 CI 成本 | macOS runner 分钟数消耗大 | 可接受；必要时改为按需构建 |
| 杀软误报 | PyInstaller 产物常见 | 已有 wheel / 源码途径，不承诺绝对不报毒 |
| 文档「总结偏差」 | README/AGENTS 里的数字易过时 | 里程碑推进后同步「技术栈声明 / 性能数据 / 能力清单 / 项目结构」四块 |

## 七、遗留项清单（逐条结论）

| 遗留项 | 结论 |
|--------|------|
| 短字符串内联（性能） | **暂不做**。当前 C VM 性能已达标；没实测瓶颈就不优化。 |
| 调试器 | **做** → 主线 B1 |
| LSP 增量同步 | **做** → 主线 B2 |
| JS 宿主 `网络` 是子进程封装 | **保持**。明确边界不是 bug，已在 `docs/embed.md` 标注 |
| Rust 宿主若干边界（整数到 i128、`**` 只支持整数指数、`压缩.打包` 写 stored、非 Windows 无 `https://`） | **保持**。都是「明确报错」而非静默算错；唯一事实源是 `docs/embed.md` |
| C VM 整数 64 位（越界报错） | **保持**。`JVal` 的 16 字节布局不能动 |
| 「本机 cargo 无法运行」旧记录 | **已核实为过时并更正**（M27 修好 rustup 硬链接后即正常） |
| 树遍历类体不支持 `通过` | **已修**（M35）：根因是误判——`通过` 从不是关键字 |
| Node / Rust 缺类变量 | **已修**（M34） |
| 测试临时文件固定名 / `build/` 目录缺失 | **已修**（M35） |
| CI 长期全红 | **已修**（M35）：根因是测试写死了开发机事实（Rust 可执行名的 `.exe`、`build/`、平台名、时区） |

## 八、推进顺序（一句话版）

```
M0–M35  ✅ 语言核心 → 工程配套 → 语言功能 A/B/C 档 → 宿主对齐 → 发布工程
  ↓
M36  主线 A 收尾  ✅ 已完成
     ✅ 三元表达式（脱糖）· 位运算内建（6 个）· 字典.合并 · 宿主同步 · 探针「无悬案」
     → **宣布【语法冻结】**：语法面不再扩张，新需求一律先问「能不能用内建/标准库」
  ↓
  ↓
M37  主线 B1：调试器最小可用（先树遍历）
  ↓
M38  主线 C：真实项目扩到 5 类场景，建立「行数比」基线
  ↓
（B2 LSP 增量 / B3 REPL 增强 / B4 格式化器 按需穿插）
  ↓
AI 友好：随主线自然生长，有机会再跑真实评测
```

**如果只做一件事（M36）**：把探针做成「无悬案」——不是为了数字好看，而是
**逼自己给每个缺口一个明确态度**。悬着的缺口会变成「用户以为有、其实没有」
的陷阱；判定清楚之后，语法面就能安心冻结，精力全部转到工具链与真实项目上。
