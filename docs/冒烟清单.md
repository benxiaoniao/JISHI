# 发行版冒烟清单

发布前，每项都要在**干净机器**上人工验证一次。按顺序勾选，任何一项失败即阻断发布。

> ⚠️ **这份清单写的是 0.2.x 的形态**（**cargo 单二进制**，运行时不依赖 Python）——
> 0.1.x 那版是 PyInstaller 包（内含 Python 运行时、约 20 MB），条目已不适用。
> 本机只能直接验证 **Windows x64**；Linux / macOS 由 CI 构建、发布后在对应机器上抽验。

## 验证环境

- [ ] 机器类型：Windows x64（**干净，无 Python**）
- [ ] 产物：`jishi-0.2.3-windows-x64-setup.exe`（安装程序）
      或 `jishi-0.2.3-windows-x64.zip`（免安装）
- [ ] 校验哈希：`Get-FileHash … -Algorithm SHA256` 与 `SHA256SUMS` 一致
      （⚠️ `SHA256SUMS` 里**不该有它自己那一行**；有的话 `sha256sum -c` 会 FAILED）

## 冒烟步骤

1. [ ] **安装（Inno 版）**：双击 `setup.exe` → 简体中文向导 → 装到
   `%LOCALAPPDATA%\Programs\jishi`（**用户级、不弹 UAC**）
   - 安装程序里勾上「加入 PATH」，或手工加
2. [ ] **新开终端**（验证 PATH 生效）：`jishi --version` → `基石 jishi 0.2.3`
3. [ ] **跑 hello**：写 `hello.jsh`（`打印("你好")`），`jishi hello.jsh` → 「你好」
4. [ ] **离线语言卡**：`jishi --ai-card` 输出语言卡（不依赖源码树）
5. [ ] **JSON 报错自愈**：写个错误脚本，`jishi 错.jsh --json-errors` 输出含 `fix` 字段
6. [ ] **沙箱**：`jishi 脚本.jsh --sandbox --json-result` 输出统一协议 JSON
7. [ ] **包管理**：`jishi 列表` 能跑；`jishi 新项目 测试` 生成脚手架
8. [ ] **医生自检**：`jishi 医生` 全 ✅（**不再查 Python 版本 / C VM / MCP** —— 单二进制里那三样不存在）
9. [ ] **MCP**：`jishi-mcp` 能被 MCP 宿主识别并跑通 `run_script`
10. [ ] **升级**（0.2.3 起有）：
    - `jishi 升级 --演练` 打印计划、**一个字节都不动**
    - `jishi 升级` 真升（先装一个旧版：`jishi-0.2.2-windows-x64-setup.exe`）——
      升完 `jishi --version` 变 0.2.3
11. [ ] **卸载（语言本体）**：`jishi 卸载 --自身`（→ 打印安装目录 + 要确认）；
    脚本里要 `--是`
12. [ ] **免安装版（zip）**：解压 → `bin\jishi.exe` 直接能跑；`install.ps1` 能装到 `~/.jishi`

## 已知限制（发布说明如实告知，不视为失败）

- Windows **安装程序**约 4 MB、**免安装包**约 2.7 MB（单二进制，无 Python 运行时）
- macOS **只有 Apple 芯片（arm64）**版，没有 Intel 版
- `配置` 模块**不含 TOML**；`时间.计时` 是唯一一处「五个引擎不同宽」的已知缺口
- ⚠️ **压缩产物各宿主字节不同**：Rust 侧写的是 `stored`（不压缩）块 ——
  完全合规、能互相解开，但**比另家的大**（见 `docs/embed.md`）

## 诚实边界

- 本机只能直接构建 + 验证 **Windows x64**
- Linux / macOS 依赖 CI 构建，发布后在对应机器上**抽验**（不假装本机验过）
