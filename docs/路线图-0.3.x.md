# 基石 0.3.x 路径规划（**安全 + 性能**）

> **2026-11-01 重排**（用户定）：0.2.10 之后的重心**从包生态挪到两件事** ——
> **① 安全审计收口**、**② 运行性能不能输给 CPython**。
> 包生态（能力声明 / 上架 / 可发现）**顺延到 0.3.1 之后**，理由见 §5。
>
> 0.2.10 及之前的路线图在 [`docs/路线图.md`](路线图.md)（那里有版本索引/里程碑索引）。

## 一、为什么重排（一句话）

> **0.2.x 把「能做」补齐了；0.3.x 要补「敢用」和「跑得快」。**

- 0.2.10 的主题是「让真实程序跑得起来」，但**跑得起来 ≠ 跑得安心**：
  `--sandbox` 是对外承诺（MCP / 在线试玩都靠它），一探就穿（§2.1）；
- 装包能装、能跑、能校验，但解压那一步**能写到包目录之外**（§2.1 第 2 条）；
- 性能一直只有「基石自己四个引擎之间」的对比，**从来没有 vs CPython 的线**。
  2026-11-01 第一次量：**几何平均 0.91–0.95x**，三个场景稳定慢（§2.2）。

## 二、实测基线（2026-11-01 · 本机 · 可复跑）

> 两条命令就能重来：`python tools/audit_security.py` 与
> `python tools/bench_vs_python.py`。**数字会变，方法不变。**

### 2.1 安全：`--sandbox` 的三条穿透 + 一处包安装越界

`python tools/audit_security.py` 的现状输出（0.2.10 发行版，Windows x64）：

| 探针 | 期望 | 实际 |
|---|---|---|
| 导入 `文件` / `表格` / `网络` / `系统` / `路径` / `压缩` / `配置` | 拦 | ✅ 全拦 |
| **内建 `打开()` 读文件** | 拦 | 🔴 **放行**（读到 README 的 33079 字节） |
| **内建 `打开()` 写文件** | 拦 | 🔴 **放行**（文件真的写出来了） |
| **`json.读文件`（白名单模块里的读）** | 拦 | 🔴 **放行** |
| 纯计算（`数学` + 文本） | 放 | ✅ 放行 |

**根因（一句话）**：沙箱是**导入守卫**（拦 `导入 X`），而「读写文件」这个能力
**不止住在被拦的模块里** —— `打开()` 是内建、`json.读文件` 在放行模块 `json` 里。
⇒ **能力必须按「能力」管，不能按「模块名」管。**

🔴 严重性：`jishi mcp` 调脚本时用的就是这个沙箱（`--stdin --sandbox --json-result`）。
也就是说，**对外宣称的隔离目前不成立**。

第二处（独立的）：

| 探针 | 结果 |
|---|---|
| 恶意包 zip 里放 `坏包/../../逃出2层.txt` | 🔴 **写到包目录之外**（`tools/probe_zip_slip.py` 复现） |

**根因**：`install_package_zip` 解压时 `tmp.join(条目名)`，**不校验条目名**。
这是包管理器里最经典的一类漏洞（PyPI 上出现过多次）。

✅ 已经做对的：按索引安装时**有校验和比对**（E4006），且没有「跳过校验」的开关。

### 2.2 性能：vs CPython 几何平均 0.91–0.95x

同一道题的**两份等价实现**（基石 / Python），同机交替取样、单轮 ≥400ms、
扣掉进程启动后取 min。两次独立跑（3 轮 / 5 轮）：

| 场景 | 第一次 | 第二次 | 结论 |
|---|---:|---:|---|
| **递归斐波那契** | **0.30x** | **0.38x** | 🔴 稳定慢 3 倍 |
| **函数调用密集** | **0.52x** | **0.37x** | 🔴 稳定慢 2–3 倍 |
| **列表构建与遍历** | **0.73x** | **0.63x** | 🔴 稳定慢 1.4–1.6 倍 |
| 文本切片 | 0.87x | 0.65x | 🟠 慢 |
| 文本下标 | 0.66x | 0.84x | 🟠 慢 |
| 字典写入密集 | 0.97x | 0.80x | 🟠 慢 |
| 算术混合运算 | 0.87x | 0.97x | 🟡 接近 |
| 字符串拼接 / 文本比较 / 文本列表遍历 | 1.01–1.14x | 0.81–0.99x | 🟡 打平 |
| 整数循环 / 内建调用 / 浮点遍历 / 布尔遍历 | 1.38–1.41x | 1.06–1.36x | ✅ 基石快 |
| **几何平均** | **0.95x** | **0.91x** | 🔴 总体不如 CPython |

> ⚠️ 单个数字有波动（±20%），**趋势稳定**：慢的三项两次都在 0.3–0.73x。
> 判据先看「趋势 + 几何平均」，别拿单次数值当结论。

**三个根因（读代码定位，可验证）**：

| # | 根因 | 证据 |
|---|---|---|
| ① | **每次函数调用都递归进 `execute()`**（`call_frame` → `self.execute(Some(depth))`） | `rust/src/lib.rs:2946` |
| ② | **`甲.追加(x)` 走完整方法分派**：`get_attr(obj,"追加")` → 分配 `BoundMethod` → `call_bound` | `rust/src/lib.rs:2569`（`LIST_APPEND`） |
| ③ | **文本下标/切片没有字符索引**，UTF-8 上按需扫描 | `GET_ITEM` 的文本分支 |

这三条恰好对应上表最慢的三行 —— **不是玄学，是可指认的代码**。

## 四、里程碑（M160–M166）

> 编号接着 0.2.10 的 M159 往后排（**不跳号、不重号**）。
> 每站一句「**做完是什么样**」—— 那是能验收的话，不是愿望。

### 推进节奏（2026-11-01 用户拍板：**先并行三站**）

| 波次 | 站 | 为什么这么排 |
|---|---|---|
| **第一波（并行）** | **M160 沙箱能力闸门** · **M161 包安装加固** · **M162 性能尺子** | 三站改的地方不重叠：M160 碰宿主的能力闸门、M161 碰包解压、M162 只加工具不动引擎。M162 不改语义 ⇒ 可以和前两站同跑 |
| **第二波（串行）** | **M163 → M164 → M165 → M166** | M163 是 VM 核心改写，**每次改动都要全量对拍**；再和其它线并行只会互相拖 |

📌 **为什么不让 M163 跟人并行**：VM 主循环一改，`check_engines`（175 语料 × 5 引擎）
就是必跑项，一轮十几分钟。两条线同时动引擎 ⇒ 每轮都在重跑、还说不清是谁破的。

### M160 · 沙箱改成「能力闸门」（主菜 🥇）

> **口径先定死（2026-11-01 用户拍板）**：**语言本体不在沙箱里**。
> 沙箱是**执行模式的开关**，不是语言的形态 —— 见 `docs/设计决策.md` **D103**。
>
> | 场合 | 沙箱 |
> |---|---|
> | 命令行 `jishi x.jsh`（**你自己写的**程序） | **全开**，没有沙箱这回事 |
> | `jishi x.jsh --sandbox`（显式要求） | 按能力闸门拒绝 |
> | **`jishi mcp`**（代码是 AI 生成的，**不是用户亲手写的**） | **默认强制**，可显式关 |
> | 在线试玩（wasm） | 天然没有文件系统，不需要 |

把「按模块名拦」改成「**按能力拦**」，四类能力统一过闸：

| 能力 | 现在拦在哪 | 改成 |
|---|---|---|
| 文件读 | 只拦 `导入 文件/表格/路径/压缩` | **所有入口**：`打开()`、`json.读文件`、`表格.读表格`、`配置`、包导入…… |
| 文件写 | 同上 | 同上（写还要单独开关） |
| 网络 | 只拦 `导入 网络` | 所有入口（含 Python 桥接的 `urllib` 等） |
| 进程 | 只拦 `导入 系统` | 所有入口（`系统.执行`、`并发` 里的执行） |

**做法（不碰语法，守住语法冻结）**：在宿主里加一个 `Capabilities` 闸门，
**每个「要碰外部世界」的内建/方法在入口处问一句**；`--sandbox` 与 `mcp` 把它设成拒绝，
**正常运行时全开**。这就把「拦导入」补成「拦能力」。

📌 口径收窄之后**反而省事**：不用再照顾「沙箱下怎么读自己刚写的文件」这种兼容包袱 ——
那些用法本来就不该在沙箱里跑。

**做完是什么样**：`jishi 脚本.jsh --sandbox` 跑任何程序都**碰不到文件系统与网络**；
`jishi mcp` 那条链路第一次真的隔离；`audit_security.py` 11 条全绿；
**普通 `jishi x.jsh` 行为一个字都不变**（这条也要有判据）。

**判据**：`tools/audit_security.py` 退出码 0；且**新增**一批「以前能过、现在该拦」的探针；
外加一条「不加 `--sandbox` 时读写照常」的对照（别把默认运行弄残）。

### M161 · 包安装加固（配菜，但必须做）

- **修 zip slip**：解压前逐条校验条目名 —— 拒绝绝对路径、`..` 段、驱动器号，
  以及解析后不在目标目录内的（用「规范化后再比前缀」，不要只做字符串黑名单）；
- `--local-zip` 安装**也提示「这个包没有校验和」**（现在静默装上）；
- 解压失败给出「哪个条目、为什么被拒」的中文错（不是一句「解压失败」）。

**做完是什么样**：一个恶意 zip 装不进来，报错直接说「第 3 个条目 `../../x` 越出了包目录」。

**判据**：`tools/probe_zip_slip.py` 变绿（现在是红）+ 一条「恶意包必须被拒」的测试。

### M162 · 性能度量基建（配菜，但没有它后面全是空话）

- `tools/bench_vs_python.py` 固化：18 场景、交错取样、输出「表 + JSON」；
- 加**基线快照** `bench/baseline_cpython.json`（带机器指纹：CPU/OS/解释器版本）——
  换机器就重录，别拿旧机器的数当标准；
- 一条 `@pytest.mark.计时` 的判据：跑基准，**几何平均 <1.0 就红**（先设 1.0，逐版抬高）。

**做完是什么样**：任何人一条命令就能回答「这版比 CPython 快还是慢、慢在哪几个场景」。

**判据**：基准进串行节；JSON 快照能被 diff。

### M163 · 函数调用扁平化（主菜 🥇，最大靶子）

**改什么**：`call_frame` 不再递归 `self.execute()`，改成「压一帧、主循环继续跑」——
CALL 返回时恢复到上一层 frame 的 ip（CPython 的 CALL 就是这么做的）。

**目标**：递归斐波那契 0.3x → **≥1.2x**；函数调用密集 0.37x → **≥1.5x**。

⚠️ **风险**：这是 VM 核心改写，牵动**异常栈展开 / 调试器断点 / `finally` / 尾调用**。
⇒ 判据不只是快，还要：五引擎逐字节对拍 0 不一致 + 调试器会话记录与改写前**逐字相同**
（`test_m39` 那套）。

**做完是什么样**：递归写法的程序和 CPython 一样快甚至更快；断点照常停、报错位置不变。

### M164 · 容器与文本的快路径（配菜 ×2）

- **`LIST_APPEND` 直通**：不再 `get_attr("追加")` + `BoundMethod` 分配，直接 push
  （用户写法 `甲.追加(x)` 的语义不变，只是**编译器认得这个惯用法**就走快路）；
- **文本下标/切片**：给长文本建「字符 → 字节」索引（按需、懒建），
  或至少在已知 ASCII 时走 `as_bytes()[i]`（UTF-8 单字节路径）。

**目标**：列表构建 0.63x → ≥1.3x；文本下标 0.66x → ≥1.2x；文本切片 → ≥1.2x。

**做完是什么样**：`甲.追加(i)` 这种最常见的列表构建，比 CPython 快。

### M165 · 数字与字典热路径（配菜）

- **整数装箱**：`Val::Int(i128)` 现在每算一次就可能分配/对齐一次 —— 小整数缓存 + 内联；
- **字典写入**：`HashMap` 的 hash 与 rehash（写入密集 0.80x）；
- **算术混合**：`//` 与 `%` 的负数语义分支（每次都要判符号）。

**目标**：字典写入 0.80x → ≥1.2x；算术混合 0.87x → ≥1.3x。

### M166 · 0.3.0 收口

- **18 场景全部 ≥1.0x，几何平均 ≥1.5x**（本机串行、两次独立取样都达标）；
- `audit_security.py` / `probe_zip_slip.py` 全绿并进 CI；
- README 性能段重写（把「vs CPython」这张表放进去 —— **这是以前没有的诚实数字**）；
- 版本号 + CHANGELOG + 站点 + 发版（照 `docs/版本收口流程.md`）。

## 五、明确不做 / 顺延

| 项 | 处置 | 理由 |
|---|---|---|
| 包生态（能力声明 / 上架审核 / 可发现） | **顺延到 0.3.1+** | 0.3.0 已经有两件主菜；再加会变成「一版塞三件事」。能力声明本身**依赖沙箱的能力模型**，先做 M160 反而是它的前置 |
| 完整沙箱（容器/seccomp 级隔离） | **不做** | 基石的沙箱是「**误用防护**」，不是「跑恶意代码的堡垒」。这条要写在文档里，别让人误解 |
| 包签名 | 不做（等真有第三方） | 先靠「校验和 + 审核」 |
| 异步 / 多线程 / JIT | 不做 | 与「中文语法习惯」无关，纯性能收益也未必划算；真要上 JIT 再单开一版 |

## 六、已拍板（2026-11-01）

### ① 沙箱口径：**默认全开 + MCP 强制** ✅

**语言本体不在沙箱里。** 沙箱是**执行模式的开关**（详见 M160 与 D103）：
命令行全开、`--sandbox` 显式、`jishi mcp` 默认强制、wasm 天然隔离。

为什么不是「默认全禁」：那会让「读自己刚写的文件」都要显式开白名单，
等于给语言本身套枷锁 —— 而**语言的价值是能写程序，不是能被审查**。

### ② 性能目标：**18 场景全部 ≥1.0x，几何平均 ≥1.5x** ✅

先「不输」再「拉开」：先让三个慢场景翻过 1.0，再谈平均分。
先追平均分去优化本来就快的场景，那是刷分不是提速。

### ③ 推进顺序：**先并行三站** ✅

M160（沙箱）/ M161（包安装）/ M162（尺子）并行 → 再串行打 M163–M165 → M166 收口。
理由见 §4 的「推进节奏」。
