## 〇、一句话

> **0.3.x = 让「别人写的包」能安全地进来。**

0.2.x 把语言能力、标准库、包管理**机制**做完了；0.3.x 要解决的是**生态侧**那三件
看不见但决定成败的事：**信任、上架、可发现**。

---

## 一、现状盘点（**2026-10-31 核实过，不是凭印象**）

| 能力 | 状态 | 在哪 |
|---|---|---|
| `jishi 安装 / 卸载 / 列表` | ✅ 有 | Rust 单二进制 `jishi-rs`（R7.6） |
| 包自述文件 | ✅ 有（叫 **`包.json`**，不是早期计划里的 `jishi.json`） | `examples/packages/*/包.json` |
| 版本约束 | ✅ 有（`>=` / `==` 两种） | 同上 |
| `jishi 发布` / `jishi 索引` / `jishi 检查` | ✅ 有 | Rust CLI（R7.6） |
| 依赖闭包 + 冲突检测 + `jishi.lock` | ✅ 有（M130） | |
| 包管理错误码 E4000–E4009 | ✅ 有（M131） | `rust/src/errcodes.rs` |
| 自建分发源 + 索引.json | ✅ 有（M146） | `https://基石.cn/packages/索引.json` |
| 自己测自己的包 | ✅ 有（`jishi 测试 <包目录>`，M147，且进 CI） | |
| **包能声明「我要读文件 / 联网」** | ❌ **没有**（`包.json` 里没有这个字段） | ← **本方向的技术核心** |
| **第三方包的上架与审核流程** | ❌ 没有（现在只有我们自己放的包） | |
| 官网「包列表」页 | ❌ 没有（索引是给 `jishi 安装` 读的，不是给人逛的） | |

📌 **结论**：0.3.x 不是「补一个服务器」，而是**补信任与流程**。
服务器那部分（静态索引）0.2.9 就够用了。

## 二、三件要做的事（按优先级）

### ① 能力声明（`能力` 字段 + 装包时告警）—— **技术含量都在这**

基石的包能 `导入 文件` / `导入 网络` / `导入 进程` —— **一个恶意包可以直接读你的文档再发出去**。
Python 也有这个问题，但 Python 生态大有扫描有举报；我们什么都没有。

做法（**这是基石能做、而 Python 做不到的事**）：

```json
{ "名字": "中文分词", "版本": "1.0.0", "能力": ["文件"], "入口": "模块.jsh" }
```

- `jishi 检查` 静态扫包的源码，**核对它用到的模块与声明的是否一致**（少了报错、多了警告）；
- `jishi 安装` 打印一行「这个包会用到：文件」，要用户确认（像 Android 权限）；
- 语言层**不新加语法**（守住语法冻结）—— 这只是一个**检查 + 提示**，不改语义。

**做完是什么样**：装一个第三方包之前，你能一眼看到「它要读你的文件」，并且装完发现它偷偷联网会被点名。

### ② 上架与审核（阶段 A：只上我们审过的包）

- 别人提 PR 到包仓库 → 我们审（源码 + 能力声明 + 自测跑得过）→ 合并 → 重新生成索引；
- `jishi 检查` 成为**审核的机器判据**（人只看它报不报红 + 代码有没有明显恶意）；
- **先不做**开放上传（阶段 B 是 0.3.x 后期，前置条件就是 ①）。

**做完是什么样**：任何一个包，**只要在索引里，就是被审过的**。

### ③ 可发现（官网包列表页 + 每条包的安装命令）

- 索引.json 已经有全部信息 → 渲染成一个静态页（**用基石自己写**，`examples/projects/基石自述站` 那套）；
- 每个包一页：说明、版本、依赖、能力声明、安装一行命令。

**做完是什么样**：不用先知道包名，就能在官网逛到有哪些包。

## 三、明确不做（避免反复讨论）

| 不做 | 理由 |
|---|---|
| 完整 semver 区间求解 / 冲突回溯 | 那是 `pip` 最复杂的部分，投入产出比极低；`>=` / `==` 够用 |
| 包签名 | 等真有第三方再说；先靠「审核 + 能力声明」 |
| 私有仓库 | 没有企业用户之前不做 |
| 沙箱默认开启 | 会让「读自己的文件」这种正常事变得别扭；等能力声明跑通再谈 |
| 自建 PyPI 式服务端 | 静态索引 + CDN 已经够（0.2.9 验证过） |
