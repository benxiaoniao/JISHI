# 测试「跳过」说明 —— 哪几项、为什么、什么时候才该担心

> README 与官网首页写着「**4319 项，4317 通过、0 失败**」。
> 差额 **2 项**是 **skipped（跳过）**，不是 **failed（失败）**。
> 这份文件逐条交代那 2 项是什么，以及本项目对「跳过」的判定标准。

## 一句话分清三个词

| 结果 | 意思 | 该怎么办 |
|---|---|---|
| **通过**（passed） | 断言跑了，而且成立 | 没事 |
| **失败**（failed） | 断言跑了，**不成立** | **要修** |
| **跳过**（skipped） | 断言**这次没跑** —— 要验的东西本机不存在，或条件不满足测了也不可信 | 看理由；**理由必须能被人复核** |

🔴 **本项目的态度**：跳过必须说得出理由，而且理由要能复核。
「懒得修」「环境没配」「CI 上偶尔过不了」**都不算理由** —— 那三种情况该让判据红
（或者把判据改成抗负载的写法，见 `AGENTS.md` §1 关于 `计时` 标记的那段）。

### 1. `tests/test_m111_release.py:188` —— 「站点未生成」

这条验「**官网首页显示的版本 == 语言版本**」。它要读 `site/index.html`，
而站点是**另一个仓库的产物**（官网仓库的 `build_site.py` 生成），
本仓库的 `site/` 是 `.gitignore` 掉的 —— 干净 checkout（含 CI）里根本没有它。

⚠️ **如实说**：这意味着这条判据**从来没有真正执行过**。它守的那件事
（「改了版本号却忘了重建站点」）现在只靠发布时手工跑 `release.sh` 兜着，
**没有机器护栏**。要么哪天改成去读官网仓库，要么就承认它是摆设 ——
但在那之前，**写在这里，别假装它在工作**。

### 2. `tests/test_m138_runner_summary.py:103` —— 「当前语料里每条都有期望文件」

这条是**反例测试**：它验「运行器把『没有期望文件』的语料记成跳过、并且逐条点名」。
可现在 `tools/自测.jsh` 的语料**每一条都有期望文件**，没有反例可造 ⇒ 跳过。

⇒ 这是「**没东西可验**」，不是缺陷。哪天有语料缺期望文件，它会自动生效。

### 曾经的第三条（已修，留档）

`tests/test_m64_rust_vm_iter.py` 的「**耗时太短、噪声占主导**」——
那条是「`遍历` 有没有退化成 O(n²)」的翻倍护栏，原来规模取 n = 2 万 / 8 万。
M163–M165 把 Rust VM 优化快之后，那两个规模的净耗时只剩 **1.3 / 4.9 ms**，
直接落进噪声区 ⇒ 判据**每次都跳过**，护栏形同虚设。

2026-11-06 已把规模改成 **20 万 / 80 万**（实测 14 / 53 ms，比值 3.8），
信号比噪声大一个量级，判据真正跑起来了。

📌 这条的教训值得记住：**判据会随实现变快而失效**。「跳过」这个机制是安全阀，
但同一个理由长期反复出现，就说明**判据本身该调了**，不是「环境问题」。

## 什么情况**不许**用跳过糊过去

- 环境能装却没装（Rust 宿主 / Node / wasm 素材）—— 那是**部署问题**，应当红。
- 「这条太难写」—— 要么写出来，要么删掉，别挂个 skip 装样子。
- 「CI 上偶尔过不了」—— 那是判据不稳，要修判据（打 `计时` 进串行节，
  或把绝对阈值改成比值断言），不是加跳过。

## 附：比「跳过」更值得关心的事

**「全量绿」不等于「没有 bug」** —— 这是两件事。判据只能覆盖它有断言的那些；
**没有判据覆盖的能力，不在这个数字里**。当前如实记着的空白（`CHANGELOG.md` 里也写着）：

- 真实**鼠标拖放**（wry 在 Windows 走 OLE `IDropTarget`，造不出真的数据对象）
- **文件对话框**、**托盘图标的点击**（模态 / 要点真图标）
- **macOS / Linux 上能不能真开窗**（CI 的 runner 没桌面，只验「编得过」）
- **真·干净机器**上装（演练用的是本机，装着 Rust/Python/Node，只是没让它们参与）
- **UAC 提权 / 非管理员账户 / 杀软拦截**

这些不是「跳过」，是「**根本没写判据**」—— 比那 2 个 skip 重要得多，
所以放在这里明着写，而不是让一个漂亮的百分比把它们盖住。
