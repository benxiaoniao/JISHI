# 前端契约（R1）—— 产物长什么样、怎么验收

> **一句话**：R 线要把前端从 Python 换成 Rust。这份文档规定
> **「前端每个阶段要产出什么」**，让两边（以及将来任何实现）用同一把尺子量。
>
> 工具：`tools/conformance.py`（`compare --from <目录>`）· 基线：`tests/conformance/`
> · 迁移路径见 `docs/架构迁移路径.md` · R0 的说明见 `docs/一致性夹具.md`
>
> ⚠️ 按 R1 的定义：**这一步不改任何行为，只定义接口。**

---

## 一、为什么要有「契约」

R0 的 `check` 验的是「**Python 前端还是老样子**」。从 R2 起要验的是
**「Rust 产出的产物，与 Python 的行为一致吗」** —— 于是需要两样东西：

1. 一个**「拿任意来源的产物来比」**的入口（`compare`）；
2. 一份说明**产物长什么样**的文档（本文）。

没有契约，两边会各写各的：Rust 侧照着「看起来对」的格式产出，
`compare` 报一堆差异，却分不清「是**实现**错了」还是「**格式**本来就不一样」。

---

## 二、版本号与变更规则

`FORMAT_VERSION = 1`（定义在 `tools/conformance.py`）

| 情况 | 要不要 +1 |
|---|---|
| **产物结构**变了（加/删字段、改字段含义、改编码） | **要** |
| 只是某个字段的**值**变了（那是行为变了） | **不要** —— 该重冻基线 |

版本对不上时，`check` 与 `compare` 会**直接报「需要重新冻结」**，
不会拿旧基线硬比（那样会得出一堆假差异）。

## 三、顶层结构

**每个语料一个 JSON 文件**，文件名 = 语料的**扁平 id**：

```
tests/cases/01_算术.jsh         →  tests__cases__01_算术.json
examples/projects/待办清单/待办.jsh  →  examples__projects__待办清单__待办.json
jishi/stdlib-jishi/统计.jsh      →  jishi__stdlib-jishi__统计.json
```

（规则：去后缀 → 把 `/` 换成 `__`。`corpus_id()` 就是干这个的。）

文件内容：

```json
{
  "语料": "tests/cases/01_算术.jsh",
  "内容哈希": "sha256:1a2b3c4d5e6f7a8b",
  "tokens":  [...],      // 词法：token 数组
  "ast":     {...},      // 语法：AST 根节点
  "bytecode": {...},     // 编译：字节码 body
  "diagnostics": null    // 诊断：null 或一个诊断对象
}
```

### ⚠️ 四个阶段各自独立，「跳过」与「失败」必须分开

某语料在**词法**就报错 → 它的 `tokens` 是 **`null`**（**不是空数组**！），
`ast`/`bytecode` 也是 `null`，而 `diagnostics` 有内容。

这样读的人一眼能分出三种情况：

| 值 | 意思 |
|---|---|
| `[...]` / `{...}` | **这个阶段正常产出了** |
| `null` + `diagnostics` 有内容 | **这个阶段报了错**（如实记录失败在哪一步） |
| **键不存在** | 这一阶段**没提供**（`compare` 会报「未提供」，**不算通过**） |

## 四、四个阶段

### 4.1 `tokens` —— 词法单元数组

每个 token：

```json
{
  "类型": "Token",
  "type": "KEYWORD",          // 词法类别（见 `jishi/tokenizer.py` 的 TT_*）
  "value": "令",              // 词面（字符串 token 给**已解转义**的值）
  "line": 2,                   // 1 起
  "col": 1,                    // 1 起，**按码点计**（见 §5.3）
  "end_col": 1,                // 结束列（含）
  "source_line": "令 a = 7"    // 该 token 所在行的**原文**（不带换行）
}
```

`类型` 是给 AST 共用的「这是个什么节点」标记（token 恒为 `"Token"`）。

### 4.2 `ast` —— 语法树根节点

**序列化规则**（通用，递归）：dataclass → `{"类型": 类名, ...字段}`
（`ast_nodes.py` 里 34 个节点类都按这个走）。

```json
{
  "类型": "Program",
  "line": 1, "col": 1,
  "body": [
    {"类型": "Assign", "line": 2, "col": 1,
     "targets": [{"类型": "Name", "line": 2, "col": 5, "名字": "a"}],
     "value": {"类型": "Number", "line": 2, "col": 9, "value": 7}}
  ]
}
```

⚠️ **难点在这儿**：`line`/`col` 要在**每个节点**上都对，
而且**脱糖的时机与位置**（`超()`、`匹配/情形`、推导式、条件表达式）
必须与 Python 侧**完全一致** —— 否则会出现「AST 一样、行为不一样」的隐蔽偏差。
这也是为什么 R5 的字节码对比**不能省**。

### 4.3 `bytecode` —— 字节码 body

**注意**：冻结进基线的是 `serialize.dump_json()` 的 body **去掉 `opcode_names`**
（那是引擎级常量表，73 个文件各抄一份纯属浪费；它在 `MANIFEST.json` 里记**一份**）。

```json
{
  "format": "jishi-bytecode",
  "version": 2,
  "checksum": "…",
  "payload": {
    "consts": [{"t": "int", "v": 7}, {"t": "str", "v": "你好"}],
    "names": ["打印"],
    "kw_names": [],
    "codes": [{
      "name": "<模块>", "params": [], "param_idx": [], "param_local": [],
      "param_cell": [], "param_kind": [],
      "nlocals": 1, "local_names": ["a"], "cellvars": [], "freevars": [],
      "firstlineno": 1,
      "instrs": [1,0,0,0,2,1, …]      // 扁平：每条 6 个 int32 = (op,a,b,c,line,col)
    }],
    "main": 0,
    "filename": "tests/cases/01_算术.jsh"
  }
}
```

**常量编码**（`_const_to_json`）：`{"t": "none"} | {"t":"true"} | {"t":"false"} |`
`{"t":"int","v":…} | {"t":"float","v":…} | {"t":"str","v":…}`。

⚠️ **超出 `Number.MAX_SAFE_INTEGER` 的整数按十进制字符串编码**
（`{"t":"int","v":"9223372036854775807"}`）—— JSON 的数字在 JS/Rust 里都是双精度，
直接写数字会丢精度。读取方按「`v` 是字符串就用大整数」处理。

### 4.4 `diagnostics` —— 第一个错误

```json
{
  "阶段": "语法",              // 词法 / 语法 / 编译（抛它的那一步）
  "码": "E0203",               // 错误码
  "标题": "这里少了冒号「：」",
  "消息": "…",
  "行": 1, "列": 1,
  "提示": "…"                   // 可能为 null
}
```

⚠️ **只有基石自己的错误（`JishiError`）才配进这里**。
前端抛别的类型 = **实现有 bug**，`freeze` 会**拒绝冻结**
（理由见 `docs/一致性夹具.md`：不能把 bug 升格成标准）。

## 五、确定性要求 —— **做不到就没法比**

产物必须**逐字节可复现**，否则每次跑都不同，比对毫无意义。四条硬要求：

### 5.1 键排序 + 中文原样

`json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True)`

- 键**排序**（不依赖插入顺序）；
- 中文**不转义**（`"令"` 而不是 `"\u4ee4"`）。

### 5.2 行尾一律 `LF`

写文件要显式 `newline="\n"`，`*.json` 在 `.gitattributes` 里钉成 `eol=lf`。
（2026-09-30 的教训：Windows 检出时被转成 CRLF，CI 上那条「行尾必须 LF」的
测试就红了，而本地是绿的。）

### 5.3 位置按**码点**计

「一个字符 = 一个 Unicode 码点」（M55 定的口径）——
`col`、`end_col`、字符串下标都按码点。⚠️ 这条对 **JS 宿主是陷阱**
（JS 字符串是 UTF-16，`s.length` 对 emoji 给 2）；Rust 侧按 `char` 数即可。

### 5.4 特殊浮点与路径

- `NaN` / `±Infinity` 写成字符串标记 `"@NaN"` / `"@Infinity"` / `"@-Infinity"`
  —— JSON 里没有这些字面量，**Rust 的 `serde_json` 会直接拒收**；
- 所有 `filename` 用**相对路径**（绝对路径换台机器就全变，还会把个人目录写进仓库）。

## 六、Rust 侧要产出什么（照着做就行）

**约定**：给你的实现一个「产出产物」的模式，把每个语料的结果写成
**一个 JSON 文件**，放在**一个目录**里，文件名用 §3 的规则。

然后验收：

```bash
python tools/conformance.py compare --from <你的产物目录>
# 只做了分词（R2 阶段）时：
python tools/conformance.py compare --from <你的产物目录> --stage tokens
```

**最小示例**（R2 只做分词时的产物，一个文件）：

```json
{
  "语料": "tests/cases/01_算术.jsh",
  "tokens": [
    {"类型": "Token", "type": "KEYWORD", "value": "令",
     "line": 2, "col": 1, "end_col": 1, "source_line": "令 a = 7"}
  ]
}
```

三条规矩：

1. **只提供你做到的那一阶段也行** —— 但 `compare` 会**如实报「未提供」**，
   默认（不带 `--stage`）时那就是**没过**。想只看分词就显式带 `--stage tokens`。
2. **语料覆盖要齐** —— 73 个语料一个都不能少（漏一个报一条「外部未产出」）。
3. ⚠️ **别为了让 `compare` 变绿而改基线** —— 基线是「Python 现在的行为」，
   它变了意味着**Python 这边**动了，要单独解释（`freeze` 前先看 `git diff`）。

## 七、已知风险（还没解决，别踩）

| # | 风险 | 说明 |
|---|---|---|
| 1 | **浮点的打印口径** | 基线里 `float` 直接写成 JSON 数字；Python 的 `repr` 与 Rust 的 `serde_json` 在**极值**上可能给出不同文本（如 `1e+30`）。语料里目前没触发，R2 之后要用「含浮点的边角语料」专门验一次 |
| 2 | **`ast` 的脱糖时机** | 见 §4.2 —— 结构一致不代表行为一致（所以 R5 的字节码对比不能省） |
| 3 | **编译期诊断只覆盖到「第一个错」** | 多错并存时，谁先报取决于遍历顺序 —— 目前三方一致，但没有专门语料钉住 |
| 4 | **运行期诊断不在本契约内** | 本契约只管**前端**（词法/语法/编译）。运行期错误（除零、越界…）在 R6 纳入夹具 |

## 八、这份契约与 R 线的关系

```
R0 一致性夹具 ── 产出：基线（数据）    ✅ 已交付
R1 前端契约   ── 产出：契约（本文）+ compare（尺子）   ← 你在这里
R2 分词器     ── 按本契约产出 tokens，用 compare --stage tokens 验收
R3 语法       ── + ast
R4 报错       ── + diagnostics
R5 编译器     ── + bytecode（四项全给，不带 --stage 全量比）
```

**R1 完成之后，R2–R5 的验收方式就固定了**：改完 → 产出 → `compare` → 看差异定位。
