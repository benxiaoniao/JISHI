# 第 10 章：包管理——代码复用与分享（M14）

写了很多函数，想在不同项目里复用？想让别人也能用你的代码？这一章讲基石的
包管理：把代码打包、安装、导入。

## 10.1 什么是「包」

一个基石包就是一个目录，里面有两样东西：

```
某包/
├── 包.json      # 包清单（名字/版本/依赖）
└── 若干 .jsh     # 代码模块
```

`包.json` 长这样：

```json
{
  "名字": "数学工具",
  "版本": "2.0.0",
  "依赖": {"基础库": ">=1.0.0"},
  "描述": "提供立方、平方和"
}
```

- `名字`：包名（唯一）
- `版本`：语义化版本（主.次.修订）
- `依赖`：这个包依赖哪些别的包，以及版本要求
- `入口`：可选，指定「对外的主模块」（不写就执行包内所有 .jsh）

## 10.2 安装包

```bash
jishi 安装 包名 --local-dir 目录          # 从本地目录装
jishi 安装 包名 --local-zip 包.zip        # 从 zip 装
jishi 安装 包名 --from-index 索引.json     # 从远端索引拉包
jishi 列表                                 # 看装了什么
jishi 卸载 包名                            # 卸载
```

安装到哪里？项目 `.jishi/packages/`（或用户目录 `~/.jishi/packages/`）。

## 10.3 导入包

装好后，代码里这样用：

```jsh
导入 数学工具 从 本地包
打印(数学工具.立方(3))    # 27
```

## 10.4 依赖是怎么生效的

如果 `数学工具` 声明了依赖 `基础库 >=1.0.0`，那么：

1. 导入 `数学工具` 时，会**自动先加载 `基础库`**
2. 校验 `基础库` 的版本满足 `>=1.0.0`（不满足报中文错）
3. 把 `基础库` 注入到 `数学工具` 的命名空间——所以 `数学工具` 的代码里
   能直接写 `基础库.平方(x)`，不用再 `导入 基础库`

如果出现「甲依赖乙、乙依赖甲」的循环，会直接报
「检测到循环依赖：甲 → 乙 → 甲」。

## 10.5 一个完整示例

`examples/packages/` 里有一个现成示例：`基础库`（提供翻倍/平方）+ `数学工具`
（依赖基础库，提供立方/平方和）。三步跑起来：

```bash
jishi 安装 基础库   --local-dir examples/packages/基础库
jishi 安装 数学工具 --local-dir examples/packages/数学工具
```

然后：

```jsh
导入 数学工具 从 本地包
打印(数学工具.立方(3))          # 27
打印(数学工具.平方和([1, 2, 3])) # 14
```

## 10.6 跑包自带的测试

好的包会**自带测试**（`*_test.jsh`，用基石自己的 `测试` 模块写）。一条命令跑完：

```bash
jishi 测试 examples/packages/图片格式转换     # 单个包
jishi 测试 examples/packages                 # 所有包（CI 上就这么跑）
```

📌 **不用先把包装一遍**：跑测试时会把「这些包所在的目录」临时当成包搜索根，
所以包里的 `导入 自己 从 本地包` 能找到自己。这样「拉下来 → 跑测试」两步就够，
也不会在你的工程里留下 `.jishi/`。

## 10.7 发布一个包（托管到自己的源）

**不用手改 JSON**，三条命令就够：

```bash
# ① 打包 + 生成索引（下载地址前缀指向你打算托管的地方）
jishi 发布 examples/packages/图片格式转换 --out dist/packages \
  --base-url https://example.com/packages/下载 \
  --index dist/packages/索引.json

# ② 有多个包时批量重建（会按包名排序，diff 稳定）
jishi 索引 examples/packages \
  --base-url https://example.com/packages/下载 \
  --zip-dir dist/packages/下载 \
  --out-index dist/packages/索引.json

# ③ 别人这样装（`--index` 也可以换成默认源之外的任意地址）
jishi 安装 图片格式转换 --index https://example.com/packages/索引.json
```

三件要知道的事：

1. **索引是静态 JSON，托管只要一个静态文件服务器** —— 没有账号体系、没有上传
   接口（这是刻意的：静态托管最不容易坏，也能直接放 CDN / 对象存储）。
2. **索引里的校验和是按 zip 内容算的**，安装时会核对；所以**发布之后别再改 zip**。
   部署侧也应该核（本项目的自建源在部署脚本里核，对不上就拒绝改写索引）。
3. 包可以声明「要多新的基石」：`"基石版本": ">=0.2.8"`。不满足时安装会被拦下
   （`E4010 基石版本不够`），修法是 `jishi 升级` —— **别去改包里的 包.json
   把要求调低**，那只会变成运行时一句「没有这个函数」。

## 10.8 小结

- 包 = 目录（含 包.json + .jsh）
- `jishi 安装/卸载/列表` 管理包，装到 `.jishi/packages/`
- `导入 X 从 本地包` 使用包
- 依赖自动递归加载 + 版本校验 + 循环检测
- `jishi 发布` / `jishi 索引` 自己能当一个包的源（静态 JSON + zip）
- `jishi 测试 <包目录>` 跑包自带的测试，**不用先装**

到这里，你已经学完了基石的全部核心特性。恭喜！🎉
