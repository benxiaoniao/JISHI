# 第 16 章：桌面程序——让程序开成一个窗口

前面所有程序都跑在终端里。这一章把程序变成一个**窗口**：有自己的图标、
没有地址栏、关掉就退出，能做成安装包给没有基石的人用。

> 配套示例：`examples/desktop/计算器.jsh`
> 跑：`jishi examples/desktop/计算器.jsh`（或在这个目录里 `jishi 计算器.jsh`）

## 16.1 一个窗口，两半

```
计算器.jsh     ← 一半：开窗、菜单、等关闭（跑在基石里）
计算器.html    ← 另一半：界面 + 页面里的那段基石代码（跑在 WebView 里）
```

为什么要两半：**界面是网页**（HTML/CSS 排版太成熟，重造不值），**逻辑是基石**
（页面里那段 `<script>` 里写的是基石源码，交给 wasm 引擎跑 —— 与命令行同一个引擎，
不是另找一套解释器）。

```jsh
导入 窗口

令 窗 = 窗口.打开({"标题": "计算器", "页面": "计算器.html", "宽": 420, "高": 620})
窗口.设菜单([...])
令 码 = 窗口.等(窗)      # 没有这一句，脚本跑完进程就退，窗口一闪而过
打印("窗口已关闭（退出码 ", 码, "）")
```

## 16.2 页面怎么拿到引擎：`/__jishi/`

`窗口.打开` 会起一个**只监听 127.0.0.1** 的小服务，把「页面所在目录」当网站根，
另外挂两个素材在 `/__jishi/` 下：

```html
<script type="module">
  const JishiWasm = (await import("/__jishi/jishi-wasm.js")).default;
  const 引擎 = await JishiWasm.load("/__jishi/jishi_wasm.wasm");
  引擎.run(源码);       // 源码就是页面里那段基石
</script>
```

🔴 **两件素材必须跟着 exe 走**（发行包里由 `打包` 带上）。少一件的表现是
**白窗口、一行报错都没有** —— 因为页面 `import` 失败就什么都不做。M173 就踩过这个。

## 16.3 🔴 一次事件 = 一次完整重跑

这是桌面这条路上**最重要**的一条，也是初学者最容易翻车的地方。

页面里每按一个键，wasm 引擎会把**整个程序重跑一遍**。所以：

```jsh
令 计数 = 0
计数 = 计数 + 1     # 每次按键都从 0 开始加 —— 永远是 1
```

状态必须存在**页面这边**（`浏览器.存本地` / `json` 编码），重跑时读回来：

```jsh
导入 浏览器
导入 json

函数 读状态()：
    令 原 = 浏览器.读本地("计算器")
    如果 原 == 空：
        返回 {"当前": "0", "累计": 0}
    令 s = json.解析(原)
    如果 类型(s) != "字典"：
        返回 {"当前": "0", "累计": 0}
    返回 s
```

📌 这不是缺陷，是**取舍**：重放模型让「页面刷新后仍在原状态」自动成立，
也省掉了状态同步的复杂度。代价就是上面这条纪律。

> 例外：调了 `图形.运行` 之后 VM 会**常驻**（第 17 章），那时状态就活在变量里了。
> 两条执行模型并存，别混着理解。

## 16.4 菜单栏

```jsh
窗口.设菜单([
    {"标签": "计算", "子项": [
        {"标签": "清空", "动作": "清空", "快捷键": "Ctrl+L"},
        {"类型": "分隔"},
        {"标签": "退出", "动作": "退出", "快捷键": "Ctrl+Q"},
    ]},
])
```

点了菜单项，页面里得有人接：

```jsh
# 页面里那段基石代码
函数 处理菜单(动作)：
    如果 动作 == "清空":
        按键("C")
    如果 动作 == "退出":
        窗口.关闭()

窗口.当("菜单", 处理菜单)
```

📌 菜单事件也只能带**一个文本参数** —— 所以 `动作` 那个名字就是分流的键。
想传结构化数据？自己 `json.转文本` 塞进去，那边 `json.解析` 出来。

## 16.5 打包：让没装基石的人也能双击

```bash
jishi 打包 examples/desktop --名字 计算器 --目标 安装包 --自带运行时
```

（`--目标` 可选 `便携,安装包,应用,压缩包`，逗号分隔；`--自带运行时` 也接受
`--with-runtime`。`jishi 打包 --help` 里没列全，以 `rust/src/packcmd.rs` 为准。）

四类产物（`--目标` 里点菜，默认全出）：

| 目标 | 产物 | 怎么用 |
|---|---|---|
| `便携` | `名字-版本.zip` | 解开就有 `app/`（你的程序）+ `bin/`（运行时），跑 `bin/jishi  app/<入口>` |
| `安装包` | `名字-版本-windows-x64-setup.exe` | **双击装**，装完有快捷方式（只有 Windows 有） |
| `应用` | `名字.app` + `.tar.gz` | macOS，双击就开 |
| `压缩包` | `名字-版本-linux-x64.tar.gz` | 解开跑 `install.sh`，入口软链进 `$PREFIX/bin` |

🔴 **`--自带运行时` 的效果**取决于 `--引擎` 指哪儿：它会把那个目录里的
`jishi` 可执行文件 + `jishi-wasm.js` + `jishi_wasm.wasm`（Windows 再加
`WebView2Loader.dll`）搬进 `bin/`。所以要么 `--引擎` 指到**装好的基石目录**，
要么就在基石的安装目录里跑 —— 否则它会停下来说
「少了引擎素材 `jishi-wasm.js`（少了它窗口是白屏，还不报错）」，这是**故意的**。

⚠️ 不带 `--自带运行时` 时，包里**只有你的程序**，对方机器上得先装基石。

🔴 打包最容易漏的三件：

| 漏了会怎样 | 谁负责带 |
|---|---|
| 页面（`.html`） | 你的目录里有什么就带什么 |
| `jishi-wasm.js` + `jishi_wasm.wasm` | `打包` 自动带（**别自己往目录里拷**） |
| 页面用的图片/音效 | 你的目录，注意**相对页面**的路径 |

## 16.6 三个坑

1. **别用 `路径.是文件(页)` 预检页面**。`窗口.打开` 先按当前目录找、找不到再按
   **脚本所在目录**找；你自己预检只按当前目录判，两边口径不同 —— 于是在源码目录里
   跑得好好的，装到别的机器上就误报「找不到页面」。
2. **`窗口.打开` 之后要有 `窗口.等`**。没有它进程直接退出，窗口闪一下就没了。
3. **网页那一半出错，窗口里看不见**。开发时用 `JISHI_WINDOW_DEBUG=1` 跑，
   宿主会把「页面到了 / 引擎起来了 / 引擎失败了」打到 stderr ——
   这是窗口里唯一能看的日志。
