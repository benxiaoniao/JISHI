# 第 17 章：游戏——从「画一个方块」到「做一个能玩的」

前面 16 章都在跟数据打交道。这一章换一件事：**让画面动起来，而且有人愿意玩**。

三个配套示例都在 `examples/desktop/`，都能零安装试玩
（官网的 `play.html` / `play-snake.html` / `play-platform.html`）：

| 示例 | 用到了什么 | 适合先看哪个 |
|---|---|---|
| `打砖块.jsh` | `图形` + 碰撞 + `声音` + `存档` | **先看这个**：物理最简单，闭环最完整 |
| `贪吃蛇.jsh` | `图形` + `随机` + `存档` | 纯网格逻辑，没有浮点，最好读 |
| `平台跳跃.jsh` | `瓦片` + `地图` + `精灵` + 相机 + 重力 | 最像「真游戏」，也最长 |

## 17.1 三个文件，一份源码

```
打砖块.jsh          桌面入口：只做 窗口.打开 + 窗口.等
打砖块_游戏.jsh     游戏本体：画 / 物理 / 计分 / 存档  ← 唯一源码
打砖块.html         页面：一块画布 + 一句 data-游戏
游戏启动.js         三个页面共用的启动器
```

为什么拆：**官网试玩页跑的是同一份本体**，它已经在页面里了，不能再 `窗口.打开`
（没有第二个窗口可开）。所以「开窗」必须独立成只给桌面的入口。

页面里只剩两行：

```html
<body data-游戏="打砖块_游戏.jsh">
  <script src="游戏启动.js"></script>
```

🔴 **游戏源码只有一份**。抄进 HTML 就会漂 —— 改了一边、另一边还是老的，
而且页面上完全看不出来。这条有判据钉着（HTML 里不许出现源码片段）。

## 17.2 一个游戏的最小骨架

```jsh
导入 图形

令 游戏 = {"x": 0.0, "分数": 0}

函数 初始化()：
    图形.准备({"宽": 640, "高": 480, "背景": "#0b1020"})
    游戏["x"] = 0.0

函数 每帧(号, 间隔毫秒)：
    令 秒 = 间隔毫秒 / 1000
    游戏["x"] = 游戏["x"] + 120 * 秒          # 每秒走 120 像素
    图形.清屏("#0b1020")
    图形.矩形(游戏["x"], 200, 40, 40, {"填充": "#fde047"})

图形.运行(初始化, 每帧)
```

三件事就位：**准备画布** → **每帧回调** → **画**。

`每帧(号, 间隔毫秒)` 的两个参数：

- `号`：第几帧（从 0 起）；
- `间隔毫秒`：距离上一帧多久。**乘它就与帧率无关** —— 60fps 和 144fps 走一样快。

## 17.3 🔴 常驻 VM：`图形.运行` 之后世界变了

平时基石是「跑一遍就结束」。调了 `图形.运行` 之后 VM **常驻**，`每帧` 只在
同一个 VM 上反复跑 —— 所以**全局状态一直在**，不需要像第 16 章那样存来存去。

但有三条必须记住：

1. **没调 `图形.运行` 的程序一点没变**（还是「一次事件 = 一次完整执行」）。
   两条执行模型并存，别混着理解。
2. **`间隔毫秒` 被掐到 100 毫秒**。后台标签页的 `requestAnimationFrame` 会停，
   切回来那一帧可能是几十秒 —— 不掐的话球一帧飞过整个屏幕（而且**看不出是 dt 的错**）。
3. **步数预算是按帧算的**（引擎替你做了）。
   它有上限是为了防死循环；常驻模式下若整场累加，玩久了会被当成死循环掐掉、
   而且越玩越早踩 —— 所以引擎每帧清零。**你不用管，但别在一帧里堆几十万次循环**，
   那会真的撞上限，看到的报错是「执行步数超过上限」。

## 17.4 图形：26 个函数，分四组

| 组 | 函数 | 备注 |
|---|---|---|
| 画布 | `准备` `宽度` `高度` `清屏` | `准备` 会**自动找 `<canvas id="画布">`**，没有就自己插一块 |
| 图元 | `矩形` `圆` `椭圆` `线` `多边形` `文本` `测文本` | 样式字典：`填充` `描边` `线宽` `圆角` `透明度` `字号` `对齐` |
| 图 | `读图` `画图` `画子图` `取像素` | 图是**异步加载**的：没加载完那几帧自动跳过绘制（不报错） |
| 输入与判定 | `按着` `按过` `鼠标` `滚轮` `碰到` `点到` `距离` | `按着` 是电平（一直按着一直真）、`按过` 是边沿（读一次就清） |

还有相机（`设相机` / `读相机`）和帧循环（`运行` / `停`）。

📌 画布只在**页面/窗口**里有。命令行和 Node 上调这些会报同一句平台错 ——
不是「没实现」，是**那边真的没有画布**。

## 17.5 碰撞：离散采样会让你穿墙

`图形.碰到(甲, 乙)` 判两个形状交不交叠。它只看**这一刻**：

```jsh
# 球一帧走 40 像素，砖只有 22 像素高 ⇒ 中间那一段没人检查 ⇒ 穿过去了
球["y"] = 球["y"] + 球["速度y"] * 秒
```

解法是**切小步**：

```jsh
令 步数 = 整数(秒 / 0.008) + 1      # 一帧切成若干个 8 毫秒
令 每步 = 秒 / 步数
令 i = 0
当 i < 步数：
    移x(每步)
    移y(每步)
    i = i + 1
```

平台跳跃里还要再分**轴**（先 x 后 y）—— 不然贴着墙走会被卡住，或者上台阶上不去。

## 17.6 声音、存档、精灵、瓦片、地图、场景

六个模块的分工：

| 模块 | 一句话 | 最容易踩的 |
|---|---|---|
| `声音` | Web Audio：载入 / 播放 / 停止 / 在放 / 设音量 / 主音量 | **第一次手势之前 `播放` 返回假**（浏览器策略），不报错。所以「点了才响」 |
| `存档` | 存 / 读 / 删 / 清，带**格式版本** | 坏了 / 版本不对 / 没存过 ⇒ **返回默认，不抛错**。存档坏了不该让游戏起不来 |
| `精灵` | 图集切帧 + 动画推进 | `更新(精灵, 毫秒)` 要每帧调，单次推进上限 1000 步（切回标签页不炸） |
| `瓦片` | 二维整数地图：`载入` `画` `碰` `取` | `-1`（或 `空`）= 没瓦片；`碰` 返回**去重升序**的瓦片号 |
| `地图` | 读关卡结构（`瓦片宽` `瓦片高` `图集` `层们`） | 命令行传**路径**、页面传**字典**（页面没有文件系统） |
| `场景` | 标题页 → 游戏中 → 结束页的状态机 | **已在当前场景 ⇒ 返回假**（否则 `每帧` 里无条件 `切` 会反复跑初始化） |

## 17.7 三条最容易翻车的写法

### ① 函数里改全局，要用容器

基石**没有 `global`**。函数里写 `分数 = 分数 + 1` 是**局部变量**（甚至可能报
「赋值之前被用到了」）。游戏状态一律放字典/列表：

```jsh
游戏["分数"] = 游戏["分数"] + 10     # ✅ 改得动
分数 = 分数 + 10                     # ❌ 局部变量，外面看不见
```

### ② 别让一帧干太多事

一帧里循环 100 万次，屏幕上就是卡住。要「慢慢做」就记一个进度，下一帧接着做。
引擎有步数预算兜底（防止死循环），但**预算是最后一道防线，不是设计手段**。

### ③ 🔴 wasm 上没有时钟

```jsh
导入 时间
# 在浏览器/窗口里，`时间.时间戳()` 走宿主通道，能用；
# 但**别指望 std::time**，也**别自己想办法取系统时间** ——
# wasm32-unknown-unknown 没有时钟，取时间会直接崩。
```

`随机` 模块就是踩过这个坑：它的种子原本取系统纳秒时间戳，于是在网页里
**一调就崩整个引擎**（报错是 `RuntimeError: unreachable`，一个字都没提随机数）。
现在由宿主喂种子，你正常 `随机.随机整数(1, 6)` 就行。

## 17.8 性能：一帧有 16 毫秒

60 帧/秒 ⇒ 一帧 **16.7 毫秒**；30 帧/秒 ⇒ 33 毫秒。超了就会掉帧。
经验值（打砖块/贪吃蛇的实测规模）：

| 每帧在干什么 | 大概多少调用 | 稳不稳 |
|---|---|---|
| 40 个矩形 + 1 个球 + 3 行文字 | ~45 次 | 稳（远低于 1 毫秒） |
| 瓦片按视口裁剪着画 | ~50 块 | 稳 |
| 满屏瓦片不裁剪（1800 块） | ~1800 次 | **别这么干** —— 传相机，让它只画看得见的 |

📌 **这一版的帧耗时还没正式量过**（200 瓦片 + 50 精灵的压测留到收口那一站）。
按上面这个量级估算没问题，但**没量就是没量**，别当成已经验过。

## 17.9 打包：双击就能玩

```bash
jishi 打包 examples/desktop --名字 打砖块 --目标 安装包 --自带运行时
```

三件必须一起带上：**页面**、**游戏本体**、**素材**（`.png` / `.wav`）。
素材路径是**相对页面**的，所以它们要跟页面同级。

`jishi-wasm.js` 与 `jishi_wasm.wasm` 由 `--自带运行时` 从 `--引擎` 指的目录搬进 `bin/`
——**别自己往程序目录里拷**（拷进去会被当成「你的文件」打进 `app/`，将来升级就对不上了）。

📌 打包会**检查 `--入口` 在不在目录里**（M188 加）：写错时它当场报
「入口「X」不在「Y」里 —— 装上之后双击会「找不到文件」」，而不是给你一个装完打不开的包。
