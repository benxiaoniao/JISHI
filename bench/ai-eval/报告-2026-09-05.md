## 一次通过率 94% 的解读

`deepseek-v4-flash` 在**未做任何微调、仅靠语言卡（~2K token 中文速查）作为系统提示**的情况下，
对 50 道基石编程题的一次通过率达到 94%。

这兑现了路线图 M8 立下的验收目标（一次通过率 ≥60%），且大幅超出。

## 3 个失败题：LLM 写基石代码的典型错误模式

| 题 | 错误 | 错误模式 | 启示 |
|----|------|---------|------|
| 011 类与对象 | `令 自身.余额 = 余额` | 构造方法里多余「令」（Python 思维：`self.x = x`） | 容错解析可提示「函数体内赋值不加令」 |
| 042 继承 | `令 动物 = 类` / `类 狗(继承 动物)` | 混淆基石「类 X 继承 Y」与 Python/JS 类表达式 | 语言卡需更醒目地标注继承语法 |
| 044 抛出与捕获 | 抛出/捕获未放进尝试块，`类型(e)` 而非 `e.类型` | 异常 API 不熟悉 | 容错解析 + 语言卡补异常示例 |

**结论**：3 个失败都是「稳定、可复现的典型错误」，不是随机波动——
它们精确指出了容错解析（M7.5）下一步该扩展的方向。

## 自愈率 0% 的原因（诚实记录）

本轮自愈率 0%，根因是**自愈机制覆盖面太窄**：

当前自愈只处理「英文关键字/内建 → 中文」的 `fix` 字段（如 `def→函数`）。
但 `deepseek-v4-flash` 在语言卡加持下，几乎不犯英文关键字错误（这类题全过），
反而犯的是**语法结构类错误**（多余「令」、继承写法、异常 API），
这些错误**当前没有生成 `fix` 字段**，自愈无从下手。

**结论**：自愈闭环的瓶颈不在循环机制（机制已验证可用），而在 `fix` 字段的覆盖面。
要让自愈率 ≥80%，需要为「多余令」「继承写法」「异常 API 误用」等结构错误也生成 fix。

## 评测集本身的迭代（本次修正）

第一轮跑出 72%，抓 LLM 原始输出后发现大量**任务描述歧义导致的假阴性**
（LLM 答案正确但被判错）。已逐条修正 8 题的任务描述，例如：

- 008 默认参数：原任务没指定名字，LLM 用「张三」被判错 → 明确「用小明」
- 027 列表索引：LLM 打印带文字标签被判错 → 明确「只打印数字不加标签」
- 041 多值返回：任务里「返回两个数」被 LLM 当函数名 → 明确函数名「两数」
- 050 日期：LLM 用解析()得到对象被判错 → 明确「用日期字符串直接调用」

修正后（温度 0）通过率 72%→94%，且每次跑结果可复现。
