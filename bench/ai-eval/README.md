# 基石评测集（JishiEval）

度量 LLM 写基石代码的**一次通过率**与**自愈率**——这是「基石是否真的容易被大模型正确生成、错了能否自愈」的硬指标。

## 结构

```
bench/ai-eval/
├── eval.py       # 评测脚本（50 题内嵌 + 自测 + LLM 接入 + 自愈闭环）
└── README.md
```

## 用法

```bash
# 标准答案自测（验证评测集本身正确，必须 100% 通过）
python bench/ai-eval/eval.py --self-test

# 列出全部任务
python bench/ai-eval/eval.py --list

# LLM 评测（需环境变量，零第三方依赖，调 OpenAI 兼容接口）
JISHI_EVAL_API_KEY=xxx \
JISHI_EVAL_BASE_URL=https://api.openai.com/v1 \
JISHI_EVAL_MODEL=gpt-4o-mini \
python bench/ai-eval/eval.py --llm          # 只测一次通过率
python bench/ai-eval/eval.py --llm --heal   # 附加自愈率统计
```

环境变量说明：
- `JISHI_EVAL_API_KEY`（必填）：API 密钥
- `JISHI_EVAL_BASE_URL`（可选）：接口地址，默认 OpenAI
- `JISHI_EVAL_MODEL`（可选）：模型名，默认 `gpt-4o-mini`

无 key 时 `--llm` 优雅降级（提示设置环境变量），不影响 `--self-test`。

## 评判标准

给定自然语言任务，LLM 生成基石代码，运行后 **stdout 与断言逐字节一致**即通过。
标准答案自测必须 100% 通过，作为「语法改动不得使一次通过率下降」的回归基线。

## 自愈闭环（`--heal`）

LLM 首次生成的代码运行失败时，读**结构化报错的 `fix` 字段**（英文关键字/内建 → 中文，
如 `{"old":"def","new":"函数"}`）做词边界文本替换，最多 2 轮。

统计两个指标：
- **一次通过率**：LLM 不改一次通过的题目比例；
- **自愈率**：未一次通过的题目中，两次内自愈成功的比例。

这两个指标正是路线图 M8 立下的验收标准（一次通过率 ≥60%、自愈率 ≥80%），
由本评测集提供脚本可复现的度量。
